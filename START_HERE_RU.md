## 2. Рекомендуемый порядок
**Где вводить.** cmd: `cd /d <папка проекта>` (там лежат `start.py`, `src`, `experiments`, `configs`). VS Code: File → Open Folder, Terminal → New Terminal; либо открыть файл и нажать Run Python File (интерпретатор: Ctrl+Shift+P → Python: Select Interpreter). Запускатели `start_quick.py`, `start_dry_run.py`, `start_tbr_enumeration.py` вызывают `start.main` с нужными опциями, допаргументы из терминала дописываются в конец; полный прогон — сам `start.py` [К]. `.vscode\launch.json` даёт четыре конфигурации без аргументов (`type` debugpy, `env` PYTHONUTF8=1): «Start: full run», «Start: quick smoke test», «Start: TBR enumeration only», «Start: dry run»; для F5 нужно расширение Python Debugger [К]. Если `python` не найден в текущем терминале, берите `py -3.14 start.py …`. Есть ещё `run.cmd` (подбирает Python), он ни разу не запускался.

**(а) `python start.py --setup-only`**. Зачем: тяжёлая сетевая часть (`.venv`, pip, torch) отдельно от счёта; ошибки установки видны сразу. Ставит и выходит с кодом 0, конфиг не пишет, ничего не запускает [К]. Здесь идёт большая загрузка. В launch.json такого режима нет — только терминал.

**(б) `python start.py --dry-run`** (или `python start_dry_run.py`). Зачем: `run_all.py` лишь проверяет и печатает команды [К]. Но `start.py` всё равно делает установку, если нужна, и пишет файл конфигурации в `outputs\_start` [К].

**(в) `python start_quick.py`** (= `python start.py --quick`). Зачем: сквозной проход до полного прогона. Набор `suite_quick`: 3 эпохи, N = 132, p ∈ {0; 0,04}; **числа НЕ результаты; длительность НЕ измерена** [К]. «Быстрый» не значит «короткий» [В]. Папка `outputs\quick_<метка>`; рисунки послешага не строятся [К].

**(г) Полный прогон: `python start.py --output-root C:\cw2out\r1`** (короткий абсолютный путь; без опции — `outputs\run_<метка>` в проекте). Объём: 220 ячеек, 5 обучений, CGR в каждой ячейке, N до 396 [Р: счёт по составу набора]. **ОЦЕНКА времени: 4,6 / 5,0 / 5,9 ч** (оптимистично / средне / пессимистично) для вашего ПК: это не измерение и не обещание; основа — один ваш запуск старого объёма, CGR при N > 132 не измерялся [К, О]. **Прерванный прогон продолжить нельзя** [К]: начинайте заново, в новой папке (существующая `plan` даёт код 3). Выдача скупая: строка `[heartbeat]` примерно раз в минуту [К]. Сон ПК, антивирус и синхронизация OneDrive — риски по документации, не проверено.

**(д) Необязательно: второй прогон `TBR_enumeration`.** `python start.py --tbr-enumeration` (основной, затем второй) или только второй: `python start_tbr_enumeration.py` (= `--tbr-enumeration --skip-main`). Это независимая реконструкция перебора простых путей; что перебирает TBR статьи — [Н]. Набор: BFS, TSR и TBR_enumeration, без GLR и CGR; папка второго прогона = основная + `_enum` (с `--skip-main`: `outputs\tbr_enum_<метка>`). Бюджеты по умолчанию: 200000 расширений на вызов, 20000000 на ячейку (`--enum-call-budget N`, `--enum-cell-budget N`). Баннер печатает худший случай на ячейку (202 с при ПРИНЯТОЙ, не измеренной скорости 100000 расширений/с, без времени симулятора) [К]; ячеек с TBR_enumeration 5 (всего в наборе 15), итого не более ~17 мин при тех же допущениях [В]. **Неполный поиск** (упёрся в бюджет): пакет ждёт, маршрута из частичной работы и запасного маршрутизатора нет, числа доставки отражают бюджет; сначала смотрите `enumeration_completeness`, бюджеты повышайте только после измерения скорости [К]. С `--tbr-enumeration` нельзя `--stages`; `--skip-main` нельзя с `--quick` и `--models` (код 2).

## 3. Что печатается при первом старте (по порядку, кратко) [К]
1. Если Python не подошёл: «This is Python X.Y; 3.10-3.14 is needed. Re-starting start.py with …».
2. `revision manifest: N files …` (строка ревизии выводится из содержимого файлов и НЕ является коммитом git).
3. Возможное `WARNING:` о длинном или синхронизируемом пути; затем `[setup] [1/4] create the virtual environment .venv`, `[2/4] update pip`, `[3/4] install torch, CPU build …`, `[4/4] install the project with the plot extra` (перед каждым — `[setup] command: …`), `[setup] running the import probe`, `import probe passed; marker written`, `[setup] versions: {…}`. При следующих стартах: `[setup] marker found` и `import probe passed`.
4. Баннер `=== ssn_hops one-command start ===`: папка проекта, python, suite, stages, папка результатов, ревизия, файл конфигурации, ОЦЕНКА времени (или пометка «SMOKE TEST»), фраза, что train и execute молчат, и про Ctrl+C.
5. `command: …` (вызов `run_all.py`), затем его вывод и `[heartbeat]`.
6. `run_all.py exit code: N (0 ok, 2 config or usage error, 3 pre-flight failure, 4 a stage failed, 130 interrupted)`.
7. При нуле: «All requested stages ended with exit code 0. This says nothing about the scientific validity of the results.», блок `Where to look:` (plan, summary.json, plots, run_all.log с пометкой `found` / `NOT found`), затем `[post-step]` (рисунки `paper_style`, не при `--quick` и `--dry-run`).

**Зелёный конец** = код 0 и `found` у перечисленного. Он НЕ означает научную верность, сходство с рисунками статьи или то, что результаты правильны: `found` проверяет лишь существование. Сбой послешага (код 13) не отменяет результат `run_all.py`.

## 4. Если остановилось
Скрипты **ничего не удаляют**; конфигурация пишется при каждом старте под новым именем, а папка `plan` или готовый `summary.json` отвергается, а не перезаписывается; повреждённый `.venv` или ненужную папку результатов удаляете вы сами.

| Код | Что значит | Что делать |
|---|---|---|
| 0 | успех | см. раздел 3 |
| 2 | ошибка команды или конфигурации (также запрещённое сочетание опций, пустой `--output-root`, отказ `--models`, слишком длинная вторая папка) | прочитать сообщение, исправить команду |
| 3 | предполётная проверка, ничего не запущено | прочитать строки `PRE-FLIGHT PROBLEM`; новая папка вместо существующей, короче путь |
| 4 | стадия упала | прислать вывод и `run_all.log` (раздел 5) |
| 130 | Ctrl+C | продолжить нельзя, начать заново; три нажатия убивают дочерний процесс |
| 10 | сбой установки (venv, pip, проба импорта, запись файла) | повторить ту же команду; при сообщении «папка .venv не пригодна / повреждена» удалить `.venv` самому |
| 11 | нет подходящего Python (или повторный перезапуск запрещён флагом `SSN_START_REEXEC`) | поставить Python 3.10–3.14 с python.org, новое окно терминала |
| 12 | проблема `config.example.json` или состава проекта | проверить, что вы в корне проекта |
| 13 | сбой послешага при успешном `run_all.py` | прислать вывод; `summary.json` не затронут |
| 14 | второй прогон упал после успешного основного | основной результат цел; прислать вывод |

Если применимо несколько кодов, 14 важнее 13, 13 важнее 0 [К]. Случаи, названные кодом: папка `.venv` есть, а python в ней нет (10, «удалите сами»); метка готовности есть, а проба импорта не прошла (10); `.venv` с python без метки — шаги pip повторяются, не удаляя ничего.
