# check_comment_only.py: проверка «та же программа, другие комментарии»

## Зачем

В семи файлах шага T131 (`policies.py`, `simulator.py`, `sim_config.py`, `contacts.py`, `tbr_policy.py`, `tbr_reference.py`, `tbr_enum.py`) должны были измениться только комментарии и тексты docstring. Три из них (`policies.py`, `simulator.py`, `sim_config.py`) после независимой проверки T131e были записаны заново в шаге T131f (правка текста комментариев, плюс новые описания). Файлы записаны целиком, поэтому одна случайно изменённая буква в строке кода изменила бы поведение. Исполнять код авторы не могли. Этот скрипт проверяет на вашем компьютере, что исходный (эталонный) файл и новый файл описывают одну и ту же программу.

**Скрипт не был запущен ни его автором, ни рецензентом.** Это текст, написанный и прочитанный глазами, но ни разу не выполненный. Сам скрипт в шаге T131f не менялся. Если он упадёт с трейсбеком или напечатает что-то странное, пришлите вывод целиком.

## Что нужно

Python 3.10 или новее. Только стандартная библиотека. Скрипт ничего не пишет на диск и не обращается к сети.

## Как запустить

Из папки, где лежит скрипт. Пути ниже даны относительно корня репозитория; подставьте свои.

Эталонные (закреплённые) файлы шести из семи модулей: `Repo_Code_2/artifacts/T108/CODE_EXPORT/src/ssn_hops/`. Новые файлы: `Repo_Code_2/artifacts/T131/REV5/src/ssn_hops/` (в ней лежат все семь файлов).

**Команда 1: режим папок, шесть пар.** Сравниваются только `*.py` с одинаковыми именами в обеих папках, то есть шесть файлов: `contacts.py`, `policies.py`, `sim_config.py`, `simulator.py`, `tbr_policy.py`, `tbr_reference.py`:

```
python check_comment_only.py --pairs-from-folders C:\репо\Repo_Code_2\artifacts\T108\CODE_EXPORT\src\ssn_hops C:\репо\Repo_Code_2\artifacts\T131\REV5\src\ssn_hops
```

Файл `tbr_enum.py` в эталонной папке T108 отсутствует, поэтому в режиме папок он не сравнивается. Скрипт печатает про него строку `INFO: tbr_enum.py exists in only one of the two folders and is not compared`; так же будут перечислены и другие файлы, которые есть только в эталонной папке. Это не ошибка, но и не проверка: `tbr_enum.py` нужно проверить отдельной командой.

**Команда 2: явная пара для `tbr_enum.py`.** Эталон этого файла лежит в T125, не в T108:

```
python check_comment_only.py C:\репо\Repo_Code_2\artifacts\T125\REV5\src\ssn_hops\tbr_enum.py C:\репо\Repo_Code_2\artifacts\T131\REV5\src\ssn_hops\tbr_enum.py
```

Порядок аргументов всегда: сначала эталонный файл, потом новый. Подойдут и обратные, и прямые косые черты. Чтобы проверить все семь пар одним вызовом, можно также перечислить семь пар `ЭТАЛОН НОВЫЙ` подряд (режим пар), но две команды выше проще читать.

Итого после двух команд должно быть видно семь строк `RESULT:` (шесть в первом выводе и одна во втором).

## Что проверяется

Для каждой пары:

1. оба файла читаются как UTF-8 и разбираются модулем `ast` (синтаксическая ошибка даёт FAIL с сообщением);
2. из обоих деревьев удаляются docstring (модуль, класс, функция), деревья сравниваются через `ast.dump`; при различии печатается первый отличающийся оператор верхнего уровня;
3. независимо сравниваются потоки токенов без комментариев, переводов строк внутри выражений и docstring;
4. построчный отчёт `difflib`: добавленные и удалённые строки делятся на COMMENT, BLANK, DOCSTRING, OTHER-TRAILING-COMMENT (комментарий в конце строки кода) и OTHER; до 20 строк OTHER печатаются с номерами;
5. для информации: размер, sha256, наличие финального перевода строки и стиль окончаний строк (LF или CRLF) обоих файлов.

## Как читать результат

- `RESULT: PASS` для пары: деревья равны и потоки токенов равны. Это значит: **та же программа** с точностью до комментариев и текста docstring.
- **PASS не значит «только добавления».** Удалённые или изменённые комментарии, удалённые docstring тоже дают PASS. Был ли шаг чисто аддитивным, читается человеком по строке отчёта `LINES: removed ...`: для этого шага число `removed` должно быть **0**. Ненулевое число `removed` это повод посмотреть, а не доказательство нарушения: `difflib` может при выравнивании длинных файлов напечатать лишние пустые строки или строки docstring как «удалённые» и «добавленные». Пришлите вывод, мы разберём такие строки.
- `RESULT: FAIL`: деревья или токены различаются (или файл не читается / не разбирается). Пришлите вывод целиком.
- Код возврата: 0, если все пары PASS; 1, если есть FAIL; 2 при ошибке в аргументах.
- Строки `NOTE:` про финальный перевод строки или стиль окончаний строк не меняют вердикт, их сравнивает читатель.
- Строки OTHER в отчёте: для файлов этого набора ожидается `OTHER 0` в обеих строках `LINES:`; допустимы только COMMENT, BLANK, DOCSTRING.

## Что прислать обратно

Весь вывод обеих команд целиком (stdout и stderr), включая FAIL и включая строки `INFO:`; код возврата каждой команды (в Windows PowerShell: `$LASTEXITCODE`, в cmd: `echo %ERRORLEVEL%`); версию Python (`python --version`). Не нужно ничего вырезать или сокращать. Если в путях есть личные данные, замените их на `...` только в строках `PAIR:`.

## Чего PASS НЕ доказывает

- Не доказывает, что тексты комментариев верны (это проверяется отдельно, чтением).
- Не доказывает, что программа правильна или что она запускается.
- Не ловит прочие повреждения: потерянный финальный перевод строки, смену окончаний строк, пробелы в конце строки, замену одного пробела на другой внутри комментария. Перевод строки и окончания строк только показываются в информационных строках.

## Известные ограничения скрипта (K-08)

- Токены docstring отбрасываются **по номерам строк**. Если на той же строке, что и docstring, после точки с запятой стоит ещё один оператор (`"""doc"""; x = 'a'`), его строковые токены тоже пропускаются, и такая замена не будет замечена в потоке токенов. В семи файлах таких строк нет (проверено чтением, не запуском), но скрипт их отдельно не разбирает.
- Текст docstring считается безопасным для поведения, только если никакой код не читает `__doc__` (например, через `inspect`). В пакете это не проверялось.
- Необычные случаи (BOM в начале файла, очень глубокая вложенность, из-за которой возможен `RecursionError`) скрипт не обрабатывает отдельно: возможен трейсбек. Это не проверялось.
- Выравнивание `difflib` может дать лишние пустые строки или строки docstring в отчёте `LINES` для длинных файлов (см. выше про `removed`).
