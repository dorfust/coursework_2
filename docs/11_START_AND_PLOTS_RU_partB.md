## 2. Опции

**`--quick`**. Пример: `python start.py --quick` (или start_quick.py). Набор `configs/suite_quick.json` (3 эпохи, N = 132, p ∈ {0; 0.04}); папка `outputs/quick_<метка>`; баннер: «числа не результаты, длительность не измерена». Послешаг с рисунками не запускается. Отказ (код 2): вместе с `--models` и с `--skip-main`. Не запрещено сочетание с `--tbr-enumeration`: вывод из чтения — тогда основной прогон «быстрый», а второй идёт на полном наборе второго прогона с обычными бюджетами.

**`--dry-run`**. Пример: `python start.py --dry-run` (или start_dry_run.py). В run_all.py передаётся `--dry-run`: проверки и печать команд, в конце «Nothing was executed. No file or folder was created» (функция run). Но start.py при этом всё равно выполняет установку (venv, pip), если она нужна, и записывает файлы в `outputs/_start`. Послешаг не запускается. С `--tbr-enumeration` проверочным будет и второй вызов. Ошибки предполётной проверки (например, существующая папка plan) в этом режиме тоже показываются.

**`--stages СПИСОК`**. Пример: `python start.py --stages plan --output-root D:\r\a`, затем `python start.py --stages train,execute,aggregate,plot --output-root D:\r\a`. Имена: plan, train, execute, aggregate, plot; порядок всегда фиксированный, как в конвейере. Отказ (код 2): пустой список, неизвестное имя, повтор имени, сочетание с `--tbr-enumeration` (второй прогон всегда plan, execute, aggregate, plot). Стадии без plan требуют `<папка>/plan/plan.json` (run_all.py, preflight_inputs, код 3); если `plan/`, `summary.json` или `plots/` уже есть, соответствующая стадия отвергается (код 3). Послешаг — только если среди стадий есть `aggregate`. Совпадёт ли строка ревизии при втором вызове и проверяют ли стадии её равенство строке плана, не установлено; вывод из чтения: при неизменённых файлах манифеста строка та же, и можно задать её явно `--revision`.

**`--output-root ПУТЬ`**. Пример: `--output-root D:\ssn\r1`. Относительный путь start.py разрешает от ТЕКУЩЕЙ папки (`Path(...).resolve()` в `choose_output_root`), run_all.py получает абсолютный. Пустая строка — код 2. run_all.py отказывает (код 3), если корень лежит внутри `src`, `.venv`, `configs`, `driver`, `docs`, `experiments` или `.vscode` проекта, если диска нет, если корень — файл, если `plan/` уже существует. Вторая папка (с `--tbr-enumeration`): `ПУТЬ_enum`; с `--skip-main`: сам `ПУТЬ`.

**`--revision HEX40`**. Пример: `--revision 0123456789abcdef0123456789abcdef01234567`. Нужны ровно 40 строчных шестнадцатеричных знаков (заглавные отвергаются, код 2). Манифест тогда не считается («revision manifest: not used»).

**`--setup-only`**. Пример: `python start.py --setup-only`. Установка и выход с кодом 0; конфиг не пишется. До установки всё же выполняются расчёт ревизии, чтение config.example.json, разбор `--models` и проверка второго пути, поэтому их ошибки приходят раньше. Отказ: вместе с `--no-setup`.

**`--no-setup`**. Установка и проба импорта пропускаются; если `.venv` есть, берётся его python, иначе текущий Python (сообщение «using the current Python»). Нехватку пакетов тогда обнаружит run_all.py (`preflight_packages`, код 3). Отказ: вместе с `--setup-only`.

**`--quiet`**. `--debug` не передаётся run_all.py: нет файла `run_all.log`, нет проб импорта и `python -m ssn_hops environment`. Вывод из чтения: сообщение об ошибке просит прислать `run_all.log`, а при `--quiet` его нет.

**`--models ПАПКА`** (повторное использование обученных GLR). Пример: `python start.py --models D:\old\outputs\run_001`. Папка — РЕЗУЛЬТАТ более раннего прогона (внутри `training/n<N>/run`) или папка, где прямо лежат `n<N>/run` (`scan_models`). Что проверяется до старта:
- в каждой `n<N>/run` есть шесть файлов: complete.json, best.json, best.pt, config.json, dataset_manifest.json, provenance.json;
- `orbit.n` в config.json равен N из имени папки; N — размер набора `suite_paper_scope.json` и число плоскостей совпадает;
- **рецепт**: разделы `model`, `data`, `train` файла config.json сравниваются с шаблоном `n132.json` (рядом с набором), слитым с `training_overrides` набора (features `adjacency_spliced_two_hop`, feature_version 1, epochs 300) и с orbit n/planes (`merge_dicts`, `recipe_differences`). Сравниваются только ключи, которые есть в шаблоне; отсутствующий ключ — `<missing>`; True и 1 считаются разными.
Любое отличие — код 2 и «нет опции, чтобы это обойти»: печатаются первые шесть отличий (пример из кода: `train.epochs: plan 300, run 3`). Так отвергаются быстрый (3 эпохи) и любой иначе обученный прогон. Размеры, которых нет в папке, будут обучены (баннер: «reuse N=…», «trained now»). Не проверяется на этом шаге: остальные поля orbit, хеши, веса; в тексте баннера: стадия execute делает свои проверки, а start.py их не проверяет и не описывает. Строже, чем нужно: любое поле трёх разделов, включая device и threads. Записывается `outputs/_start/models_<метка>.json` (N → путь к run), он указан в `plan.models`. Отказ (код 2): пустая строка, не папка, нет `n<N>/run`, неполный прогон, N вне набора, другое число плоскостей, отличие рецепта; вместе с `--quick`; вместе с `--skip-main`. Не установлено: пройдёт ли модель прогона 3a (ни один настоящий config.json пользователя не читался); примет ли execute контрольную точку, обученную более старым кодом, при изменённых хешах исходников.

**`--tbr-enumeration`**. Пример: `python start.py --tbr-enumeration`. После УСПЕШНОГО основного прогона (код 0, послешаг не прерван) идёт второй вызов run_all.py (`run_second`) со своим конфигом `outputs/_start/config_tbr_enum_<метка>.json`: набор `configs/suite_tbr_enumeration.json`; стадии plan, execute, aggregate, plot (train не нужна); в `plan`: `baselines_only` true, `include_native_tbr` false, `include_tbr_enumeration` true, оба бюджета записаны явно; `aggregate.reference` = TBR_style_hop_oracle. Баннер `print_enum_banner` печатает худший случай на ячейку: (бюджет ячейки + бюджет вызова) / 100000 расширений в секунду; скорость 100000 в код ПРИНЯТА, не измерена. Ручной расчёт по умолчанию: (20 000 000 + 200 000) / 100 000 = 202 с (около 3,4 мин) на ячейку, ячеек TBR_enumeration в наборе 5 (`count_enum_cells`), итого не более 1010 с (около 17 мин) при принятой скорости, без времени симулятора; при скорости в пять раз меньшей — в пять раз дольше. Баннер просит сперва измерить секунды на расширение по `summary.json` и только потом повышать бюджеты. Если основной прогон упал, второй не запускается.

**`--skip-main`** (только с `--tbr-enumeration`; пример: `python start.py --tbr-enumeration --skip-main` или start_tbr_enumeration.py). Основной прогон пропускается; папка `outputs/tbr_enum_<метка>` и есть папка второго прогона; код run_all.py возвращается без замены на 14. Отказ (код 2): без `--tbr-enumeration`, с `--quick`, с `--models`. Путь второй папки в этом режиме проверяет только run_all.py (код 3).

**`--enum-call-budget N`, `--enum-cell-budget N`** (только с `--tbr-enumeration`). Пример: `--enum-call-budget 100000 --enum-cell-budget 5000000`. `budget_arg`: только десятичные цифры, больше нуля (без знака, без `1e6`, без `_`), иначе код 2. По умолчанию 200000 и 20000000 (ENUM_CALL_DEFAULT, ENUM_CELL_DEFAULT); бюджет ячейки намеренно меньше библиотечного (часть C).

## 3. Второй запуск
Это новый вызов с новой меткой: новая папка `outputs/run_<метка>` и новые файлы в `outputs/_start`. Если `.venv` и метка `ssn_ready.json` на месте, повторяется только та же проба импорта (до 900 с; при `--no-setup` и она). Прерванный или упавший прогон продолжить нельзя: надо начинать заново, а старая папка остаётся нетронутой (возобновления нет).

## 4. Что куда пишется
| Место | Что | Заметка |
|---|---|---|
| `.venv/`, `.venv/ssn_ready.json` | окружение, метка готовности | метка создаётся режимом «x» |
| `outputs/_start/` | `config_<метка>.json`, `models_<метка>.json`, `config_tbr_enum_<метка>.json` | при занятом имени `_2`…`_99`; существующий файл не трогается |
| `<папка>/plan/` | план, подпапка `logs` со статус- и stderr-файлами заданий | run_all.py |
| `<папка>/summary.json`, `<папка>/plots/` | результат агрегации, рисунки run_all.py | существующие отвергаются |
| `<папка>/run_all.log` | копия вывода run_all.py (без `--quiet`) | открывается в режиме добавления («a») |
| `<папка>/paper_style/` | рисунки послешага | не при `--quick` |
| `src/ssn_hop_reconstruction.egg-info` | побочный эффект редактируемой установки pip | по docstring start.py |
Ничего не удаляется: start.py ничего не удаляет и создаёт свои файлы только в режиме «x»; run_all.py отвергает существующие plan, summary.json, plots. Свои файлы start.py пишет в своей папке (`.venv`, `outputs/_start`) и в папке результатов, которую `--output-root` может поместить в другое место. Запускаемые программы этим не покрыты: pip заменяет файлы внутри `.venv` (например, обновляя себя), редактируемая установка может создать `src/ssn_hop_reconstruction.egg-info`, Python — папки `__pycache__`. Что лежит внутри папок стадий train и execute, я не читал (код стадий — src/ssn_hops/experiments.py).
