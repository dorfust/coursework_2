# 02. Среда моделирования. Часть 4 из 8: geometry.py

Файл: `src/ssn_hops/geometry.py` (5747 байт). Условные обозначения — в `02_ENVIRONMENT_RU.md`.

## 1. Назначение

Докстринг: «Circular ECI geometry in km/seconds, independently written from analytic formulas.» Модуль:
- создаёт «траекторию» созвездия — случайно выбранные (по сиду) долготы восходящих узлов и фазы плоскостей (`make_trajectory`, класс `Trajectory`);
- по траектории и времени вычисляет положения всех спутников (`Trajectory.positions_km`);
- по положениям строит двоичную матрицу смежности и матрицу расстояний (`graph_from_positions`) по правилу «дальность ≤ `range_km`» и «прямая видимость над Землёй».

## 2. Входы и выходы
- `make_trajectory(config: OrbitConfig, seed: int)` → `Trajectory`.
- `Trajectory.positions_km(time_s)` → `numpy.ndarray` формы `[N, 3]`, `float64`, километры.
- `graph_from_positions(positions_km, config)` → кортеж `(adjacency, ranges)`: `adjacency` — `bool`-матрица `[N, N]`; `ranges` — `float64`-матрица `[N, N]` расстояний в км между всеми парами (включая неспособные к связи; на диагонали нули).
- Файлов не пишет и не читает.

## 3. Система координат и положения (в коде написано / вывод из чтения)

Система: инерциальная геоцентрическая («ECI» в докстринге), единицы — километры и секунды. Вращение Земли в коде не учитывается (вывод из чтения: нет ни одного члена, зависящего от угловой скорости Земли; вычисляется только движение спутников).

В `Trajectory.positions_km(time_s)` (все названия — из кода):
- `per_plane = n // planes`; индексы спутников: `plane = np.repeat(np.arange(planes), per_plane)`, `slot = np.tile(np.arange(per_plane), planes)`. Вывод: номер спутника `id = plane * per_plane + slot`; спутники одной плоскости идут подряд.
- `radius = earth_radius_km + altitude_km`; угловая скорость `omega = sqrt(mu_km3_s2 / radius**3)`.
- Аргумент широты: `phase = (2π·slot/per_plane + plane_phase_rad[plane] + omega·(time_s − epoch_s)) mod 2π`.
- Далее при `i = inclination_deg`, `Ω = raan_rad[plane]`, `u = phase`:
  `x = radius·(cosΩ·cos u − sinΩ·sin u·cos i)`,
  `y = radius·(sinΩ·cos u + cosΩ·sin u·cos i)`,
  `z = radius·sin u·sin i`. Это стандартное круговое движение, записанное прямо в коде (`np.column_stack`).
- Проверка: `time_s` должно быть конечным (`math.isfinite`), иначе `ValueError("time_s must be finite")`. Метод не вызывает `config.validate()` (конфигурация проверяется в `make_trajectory`).

`Trajectory.period_s` = `2π·sqrt(radius³ / mu)` (не зависит от `epoch_s`).

### Ручной расчёт для значений по умолчанию (`OrbitConfig`: 6371.0, 1050.0, 398600.4418; `n=132`, `planes=12`)
- `radius = 6371 + 1050 = 7421 км`.
- `radius³`: `7421² = 55 071 241`; `· 7421 = 408 683 679 461 км³`. Делим на `398600.4418` → примерно `1 025 297 с²`; квадратный корень ≈ `1012.6 с`.
- Период `≈ 2π · 1012.6 ≈ 6362 с` (около 106 минут); `omega ≈ 1/1012.6 ≈ 9.88·10⁻⁴ рад/с`. Результат приближённый, получен вручную.
- Спутников в плоскости: `132 / 12 = 11`; угловой шаг по слотам `2π/11` (≈ 32.7°).
- Хорда между соседними спутниками одной плоскости: `2·radius·sin(π/11) = 2·7421·0.28173 ≈ 4181 км`. Она больше `range_km = 3500`. Хорда для других пар слотов одной плоскости `2·radius·sin(kπ/11)`, `k = 1…5`, ещё больше. Вывод (ручной расчёт и чтение): при значениях по умолчанию спутники одной и той же плоскости не связаны между собой; связи возможны только между разными плоскостями. Заметьте: взаимное расположение внутри плоскости не зависит от случайных фаз (случайно только смещение всей плоскости).
- Хорда, ограничиваемая только Землёй: если отрезок между двумя спутниками на радиусе `7421` касается сферы радиуса `6371`, его длина `2·sqrt(7421² − 6371²) = 2·sqrt(55 071 241 − 40 589 641) = 2·sqrt(14 481 600) ≈ 2·3805.5 ≈ 7611 км`. Так как `3500 < 7611`, при значениях по умолчанию дальность `range_km` является более жёстким ограничением, чем геометрия Земли, для двух спутников на одинаковой высоте; прямая видимость могла бы отсечь пары только при большем пределе дальности (вывод).

## 4. make_trajectory — где и как входит случайность

```
make_trajectory(config, seed):
    config.validate()
    integer(seed, "phase seed", 0); seed < 2**32 иначе ValueError
    rng = np.random.default_rng(seed)
```
Генератор — `numpy.random.default_rng(seed)` (локальный объект; глобальное состояние `numpy.random` не затрагивается). Порядок обращений к `rng` фиксирован кодом:
1. `rng.uniform(0, 2π)` внутри выражения для `raan`: `raan = (2π·plane/planes + u1) mod 2π` — равномерное разнесение `planes` плоскостей по долготе узла на полный круг плюс один общий случайный поворот (комментарий кода: «Uniform RAAN spacing, one global random rotation, explicit floating-point F»).
2. `rng.uniform(0, 2π)` для `phase = 2π·walker_f·plane/n + u2`.
3. Только если `phase_mode == "independent_plane_offsets"` (значение по умолчанию): `phase = phase + rng.uniform(0, 2π, size=planes)` — независимое случайное смещение каждой плоскости.
Итог: `Trajectory(config, seed, raan, phase mod 2π)`, где `plane_phase_rad` — массив длины `planes`.

Вывод из чтения: при `phase_mode == "walker"` вторая и третья случайные величины не дают независимых смещений плоскостей: сдвиг фаз плоскостей детерминирован членом `2π·walker_f·plane/n` плюс общий случайный сдвиг `u2`. При `independent_plane_offsets` член с `walker_f` присутствует, но по распределению перекрывается независимыми смещениями; на конкретные значения при фиксированном сиде `walker_f` всё же влияет.

Одинаковые `(config, seed)` дают одинаковую траекторию (вывод из чтения: вся случайность — детерминированный `default_rng(seed)`; побитовая воспроизводимость между версиями `numpy` кодом не гарантируется).

## 5. Класс Trajectory
Поля: `config` (OrbitConfig), `seed`, `raan_rad`, `plane_phase_rad` (массивы). Методы:
- `metadata()` → `{"orbit": asdict(config), "seed", "raan_rad": [...], "plane_phase_rad": [...]}` (`asdict` импортируется внутри метода).
- `trajectory_id` → `content_hash(metadata())`.
- `period_s`, `positions_km(time_s)` — см. выше.
Вывод из чтения: класс объявлен `frozen=True` с полями-массивами; сравнение экземпляров и хэширование по полям для таких классов, как правило, неприменимо к массивам; в самом коде такое сравнение не используется.

## 6. graph_from_positions — видимость и смежность

Докстринг: «One shared physical/advertised graph. Returns (binary adjacency, ranges_km).» и «Range comparison is inclusive; a tangent to the spherical Earth is visible. No atmosphere, antenna constraints or interpretation of the unresolved 50.4 deg.» (в коде названо: упрощения и неразрешённый параметр «50.4 deg»).

Шаги (в порядке кода):
1. `config.validate()`.
2. `xyz = np.asarray(positions_km, dtype=np.float64)`; форма должна быть `(n, 3)`, значения конечные, иначе «positions must be a finite [N,3] array in km».
3. Если норма любого положения меньше `earth_radius_km` → «positions inside Earth are invalid».
4. `delta[i, j] = xyz[j] − xyz[i]`, `squared = Σ delta²`, `ranges = sqrt(squared)`.
5. `adjacency = ranges <= range_km` (нестрогое сравнение).
6. Если `earth_los` включён: для каждой пары, прошедшей проверку дальности, берётся отрезок `p_i → p_j`, находится ближайшая к центру Земли точка отрезка: `t = clip(−(p_i·Δ) / |Δ|², 0, 1)` (при нулевой длине `t = 0`), `closest = p_i + t·Δ`; связь допускается, если `|closest|² >= earth_radius_km²` (нестрогое: касание видимо). В коде есть две ветви: при C-непрерывном массиве проверка выполняется только для пар, прошедших дальность (по комментарию — оптимизация, эквивалентная «базовому» варианту, у которого то же выражение считалось для всех `N·N` пар и затем объединялось по «И»); иначе (не C-непрерывный вход) — исходная полная форма с `adjacency &= visible`. Комментарий называет это оптимизацией «OPT-7», сравнивает с ревизией «BASELINE b6f5f516» и отсылает к служебному документу, раздел 3 (аргумент о побитовом равенстве); этот документ не входит в экспорт, поэтому проверить эквивалентность ветвей по экспорту нельзя. Диагональ в оптимизированной ветви обрабатывается так же (расстояние 0).
7. `adjacency &= adjacency.T` («Conservative treatment of a floating-point tangent») — симметризация логическим «И»; затем диагональ обнуляется.
8. Возврат `(adjacency, ranges)`.

Правило связи, итог (вывод из чтения): ребро `(i, j)` есть, если `|p_i − p_j| ≤ range_km` и (при `earth_los`) отрезок не заходит внутрь шара радиуса `earth_radius_km`. Атмосфера, антенны, углы места и ограничения числа связей на спутник не учитываются (в докстринге: «No atmosphere, antenna constraints»). Число соседей не ограничено.
