## 1. Что такое конфигурация

Набор не содержит параметров расчёта. Он **называет по имени файла** две готовые конфигурации из своей папки и накладывает на них надбавки. Во всех трёх наборах: `core_template` = `n132.json`, `simulation_template` = `simulation_n132.json`.

**Ядро `n132.json`** (`schema_version` 2) [К]: блок `orbit` (N 132, плоскости 12, высота 1050.0, наклонение 53.0, дальность 3500.0, проверка Земли на линии), блок `data` (сеятели обучения, проверки и теста; 24 снимка на траекторию; шаг 120.0 с), блок `model` (`gcn_width` 32, `dense_width` 64, `features` `adjacency_spliced_two_hop`, `feature_version` 1, ориентация `destination_candidate`) и блок `train` (`seed` 17, `epochs` 100, `batch_size` 4, `learning_rate` 0.001, `patience` 15, `device` `cpu`, `deterministic` true, `optimizer` `Adam`).

**Симуляция `simulation_n132.json`** (`schema` `ssn-simulation-config-v1`) [К]: тот же `orbit`; `phase_seed` 401, `traffic_seed` 501, `failure_seed` 601; `tick_s` 0.1, `traffic_end_s` 600.0, `observation_end_s` 900.0, `packet_bytes` 18000, `ttl_s` 300.0, `rate_bytes_s` 12500.0, `light_speed_km_s` 299792.458, `failure_probability` 0.04.

**Соединение** [К, `resolve_suite` и `merge` в `src/ssn_hops/experiments.py`]: путь шаблона = папка набора / значение поля; `training_overrides` накладывается на ядро, `simulation_overrides` — на симуляцию; словари сливаются рекурсивно, список заменяется целиком. Значения шаблона перекрываются: ключ `train.epochs` перекрыт во всех трёх наборах — в одном вниз (3), в двух вверх (300), и значение шаблона 100 не использует ни один из трёх; `failure_probability` и три сеятеля приходят из сеток и кортежей набора (§ 4).

Полный перечень ключей обоих шаблонов со значениями, с ограничениями из кода и с указанием, где смысл поля не установлен, — § 10.

## 5. `policy_scope`

- Схема [К, `validate_policy_scope`]: непустое отображение «имя политики → фильтр»; имена только из четырёх `POLICIES`; в фильтре допустимы `n`, `failure_probability`, `seed_tuple_indices`; отсутствующий ключ значит «везде», **пустой список — «эта политика нигде»**; значения должны быть в сетках набора; неназванная политика планируется везде; сценарий без политик отвергается с `ValueError`.
- В `suite_tbr_enumeration.json`: `{"CGR_contact_plan": {"n": []}}` — пустой список по N исключает CGR из всех сценариев набора [К по правилу выше; В по файлу]. Отсюда 5 сценариев по 3 политики = 15 ячеек [Р].
- Два других набора о политиках не говорят ничего: это не «все политики», а «ограничений не задано» — список задают опции плана [К]. Следствие [К]: `run_all.py` (`check_suite_semantics`) и `make_plan` отказываются планировать `plan.include_native_tbr: true` вместе с набором, у которого есть `policy_scope`.

**Правило счёта.** Различных листьев — **56**: 12 в блоке `orbit` (блок входит в оба файла, и значения в нём совпадают [В — полевое сравнение]), 27 вне `orbit` в `n132.json` и 17 скалярных ключей верхнего уровня в `simulation_n132.json`. **Как файл превращается в конфигурацию** [К]. `config.from_dict` и `sim_config.from_sim_dict` отвергают неизвестный ключ на любом уровне (`ValueError`), а пропущенный ключ заменяют умолчанием поля датакласса; вложенный `orbit` файла симуляции разбирается тем же `OrbitConfig`. Поэтому набор ключей в файле и набор полей датакласса — разные вещи: чего в файле нет, то берётся из кода (§ 10.3, § 10.4). Проверки `integer()` требуют `type(value) is int` [К]: значение вида `132.0` в целочисленном поле отвергается, как и булево значение в `positive()` и `finite_number()`.

### 10.6 Что код вычисляет из этих полей

- `horizon_tick` = `ticks(observation_end_s, tick_s)`, `ttl_ticks` = `ticks(ttl_s, tick_s)` [К]; `ticks()` требует конечного неотрицательного числа и кратности `tick_s` с абсолютным допуском 1e-7, иначе «must be a multiple of tick_s» [К].
- `service_ticks(size_bytes, rate_bytes_s, distance_km, light_speed_km_s, dt)` = `max(1, ceil(raw - 1e-12))`, где `raw = (size/rate + distance/c) / dt` [К]. Слагаемое сериализации и слагаемое распространения складываются, результат округляется вверх, нижняя граница — один тик.
- `Config.sha256` — sha256 канонического JSON (`sort_keys=True`, без пробелов, `allow_nan=False`), поэтому порядок ключей и пробелы файла хеш не меняют [К по `canonical_json` и `content_hash`]; `Config.data_key` считается только по `orbit` и `data` [К].
- `SimulationConfig.trace_key` включает `orbit.n`, `traffic_seed`, `tick_s`, `traffic_end_s`, `arrival_interval_s`, `packet_bytes` [К]; `failure_probability`, сеятель фазы, сеятель отказов и `rate_bytes_s` в него не входят [В по составу словаря].

### 10.7 Ручной расчёт по значениям шаблона симуляции [Р]

- 600.0 / 0.1 = 6000 тиков до конца трафика.
- 900.0 / 0.1 = 9000 тиков горизонта; совпадает с `horizon_tick` [К].
- 300.0 / 0.1 = 3000 тиков времени жизни; совпадает с `ttl_ticks` [К].
