# 07. Ограничения папки и кода: сводка

Документ собирает ограничения, которые следуют из `README.md`, групп `docs/01`-`docs/06` и из текста кода. Он короткий и ничего нового о работе кода не сообщает. Ничего не запускалось: ни одна фраза не означает, что код работает, проходит тесты или даёт результаты; результатов экспериментов в папке нет. Метки: «в коде написано» — цитата или пересказ кода; «вывод из чтения» — заключение без запуска; «ручной расчёт» — арифметика, показанная в тексте. Поправки к формулировкам, наблюдения и непроверенные пункты — в `docs/ERRATA_RU.md` и `docs/ERRATA_RU_part2.md`.

## 1. Что такое эта папка

- Файлы `src/ssn_hops/` (25) и `configs/` (5) заявлены как дословная копия исходных файлов. Сравнить их с исходным репозиторием можно только по списку git blob SHA, который хранится вне папки; получатель без исходного репозитория этого не может.
- Описание в `docs/` получено только чтением. Оно не проходило независимой проверки на момент написания (статус со временем может измениться).
- Описание и чтение кода выполнены одним и тем же способом (чтение без запуска), поэтому ошибки чтения могут быть связаны между собой: одно и то же недопонимание способно попасть и в описание, и в «проверку» описания. Для этого описание не проверялось запуском ни в одном месте.
- В коде написано, что это независимая реконструкция, а не исходный код авторов (`__init__.py`: «Independent reconstruction, not original author code. Runtime not validated.»; `provenance.SOURCES["implementation"]`: «independent reconstruction, not original code or published-performance equality»; `experiments.py`, справка `parser`: «RECONSTRUCTION sweeps; never authors' results»).

## 3. Платформа и окружение (из кода и чтения)

- Драйвер рассчитан на POSIX: `run_cell` и `train_unit` при другой ОС бросают `OSError` (в коде написано: «Windows-native is out of scope», «POSIX only (Linux, WSL2)»).
- `finish.py` создаёт файлы жёсткой ссылкой `os.link`; рабочий каталог должен её поддерживать (в коде написано, `FinishIOError`).
- `driver/ledger.py` читает `/proc/cpuinfo` и `/proc/meminfo`; при отсутствии значения становятся `None` (вывод из чтения).
- `torch` нужен широко: `provenance.py` импортирует его на уровне модуля, поэтому его требуют `cli`, `data`, `training`, `simulate` (в том числе команды `environment` и `simulate trace`). `torch_geometric` нужен модели и обучению, а через `cli` → `training` → `model` — и всем командам `python -m ssn_hops` (вывод из чтения; см. `ERRATA_RU.md`, A18).
- `matplotlib` подключается лениво, только командой `plot`, и в метаданных исходного проекта не объявлен.
- Python 3.10 или новее: аннотации вида `int | None` вычисляются при определении (`simulator.py`, `tbr_policy.py`).
- Диапазоны версий (`python >=3.10,<3.15`, `numpy>=1.26,<3`, `torch>=2.6,<3`, `torch-geometric>=2.6.1,<3`) — пересказ метаданных, которых в папке нет; совместимость конкретных версий не установлена; файла фиксации версий нет и не создавался.

## 4. Поведенческие ограничения (в коде написано или вывод из чтения)

- План привязан к абсолютному корню (`plan_io.check_binding`: иначе «root mismatch») и к хешам всех `*.py`, лежащих рядом с `experiment_io.py` (25 файлов пакета); изменение любого файла или посторонний `*.py` отвергает запуск.
- Умолчание `--slices` у `run_cell` и `train_unit` — `Path(__file__).resolve().parents[1] / "slices.json"`; в раскладке экспорта такого файла нет; обход (вывод из чтения): `--slices configs/slices_m1b_cgr.json` — нет в поставке.
- Нативная политика `TBR_bounded_exhaustive_reference`: умолчание `max_nodes` равно 12, `n = 132` по умолчанию; без `--tbr-max-nodes` запуск отказывает до создания вывода (проверка `cfg.orbit.n > policy.max_nodes`).
- Бюджет времени драйвер не обеспечивает: `ledger.py` только суммирует минуты; числа 700 нет ни в одном файле драйвера. Есть лимиты на ячейку (`--cap-minutes`), на обучающую единицу (по умолчанию 120 минут) и на «стену» (`--wall-minutes`).
- Строки схем: `simulator.py` пишет `ssn-simulation-result-v1`, `simulate.run_single` заменяет её на `ssn-simulation-result-v2` (нативная — `ssn-native-exhaustive-simulation-result-v1`); результат прямого вызова `simulate()` остаётся с `v1`.
- Существующие файлы не перезаписываются (режим `"x"`, `mkdir(..., exist_ok=False)`); обучение не возобновляется; после остановки по лимиту единица обучения удаляется целиком (`--discard`) и обучается заново.
- `--revision` — строка из 40 hex, заданная вызывающим; git не читается; регистр: `experiment_io.revision` требует строчные, `cli.revision` и `simulate.revision` принимают верхний регистр.
- После записи `execution_started.json` команда `experiments execute` отвергается (по docstring); параллельная запись в один журнал не защищена блокировками (в коде их нет).

## 5. Ограничения моделирования, названные кодом или видимые в нём

Проверено по тексту `geometry.py` и `contacts.py` (прочитаны целиком); пункты о политиках — по таблице `docs/01` часть 3, §11 и частям `docs/04`, в этом файле с `policies.py` заново не сверялись.

- Система координат: «Circular ECI geometry in km/seconds, independently written from analytic formulas.» (`geometry.py`). Вращение Земли не моделируется (в формуле положений нет членов с угловой скоростью Земли); эксцентриситет только 0 (`OrbitConfig.validate`).
- Связь определяется только дальностью и прямой видимостью: `range_km = 3500.0`, `earth_los = True`; docstring: «No atmosphere, antenna constraints or interpretation of the unresolved 50.4 deg.» Ограничения угла места, антенн и числа соседей в коде нет.
- Время квантовано: `tick_s = 0.1`; `ticks()` требует кратности; семантика в `ContactPlan.metadata()`: «true sample at k holds on [k*dt,(k+1)*dt); ends allow completion». Длительность передачи — `max(1, ceil(raw − 1e-12))` тиков с дальностью на момент старта; при умолчаниях 15 тиков (ручной расчёт, `docs/02` часть 3).
- Раскладка признаков и вся постановка помечены кодом как реконструкция (общая метка пакета — раздел 1); отдельная метка именно у раскладки признаков в этом файле с кодом не сверялась; значение по умолчанию — «topology-only (paper-faithful)», канал задержки — «optional extension» (комментарий в `experiments.py`).
- `TBR_style_hop_oracle` (`HopOracle`) — оракул числа хопов: поиск в ширину по текущей смежности; множество посещённых узлов не использует. В подписи рисунков: «BFS practical alternative; NON-COMPARABLE to Fig.5» (строка `experiment_plots.py`; «Fig.5» — рисунок оригинальной статьи, документа-источника в экспорте нет).
- `TSR_source_dijkstra`: путь строится один раз в источнике по текущей топологии и не чинится (`repair: none`).
- `CGR_contact_plan`: зависящий от времени поиск по плану контактов; docstring: «time-dependent Dijkstra with WAITING CLOSURE on every edge». Очереди, резервы буферов и случайные отказы план не учитывает.
- `GLR`: оценка оставшихся хопов моделью; оракула достижимости нет — без кандидата пакет ждёт.
- Одна копия пакета; предел хопов `hops >= 2 * n` не задаётся конфигурацией; испытания отказа — только внутри передачи (14 испытаний на 15-тиковый хоп, ручной расчёт).
