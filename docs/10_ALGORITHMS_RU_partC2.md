# 10. Алгоритмы. Часть C2: `TBR_enumeration` и нативный ограниченный эталон

Файлы: `tbr_enum.py` (класс `TBR_enumeration`, `name = "TBR_enumeration"`, ревизия 5), `tbr_policy.py` (`TBR_bounded_exhaustive_reference`), `tbr_reference.py` (`exhaustive_simple_path_reference`). Метки — индекс. Ничего не запускалось автором описания — это метка метода, а не состояние проекта; о состоянии проекта — вступление к индексу набора `10_ALGORITHMS_RU.md`.

## 1. Назначение

Это два способа принять решение полным перебором простых путей — вместо BFS части C. `TBR_enumeration` — **необязательная** политика (по умолчанию выключена, включается опцией плана). Нативный эталон — политика с жёсткими границами (что она более ранняя — по истории проекта; по рассмотренным файлам это не установлено); она служит **эталоном эквивалентности**: в коде `tbr_enum.py` написано, что решение `TBR_enumeration` совпадает с решением `exhaustive_simple_path_reference`, **когда поиск завершился**. Обе — независимые реконструкции: в коде написано «independently specified, NOT author TBR code» и «not the paper's brute force».

## 2. Что читают

`TBR_enumeration.choose`: `packet.location`, `packet.destination`, `packet.visited`; `context.adjacency`, `context.permitted_neighbors`, `context.tick`. Не читает `ranges_km`, размер, TTL, `cfg`. `TBR_bounded_exhaustive_reference.choose` передаёт ядру те же поля плюс границы.

## 3. Что именно решается (определение, в коде написано)

Допустимые пути: простые (без повторов узлов) пути от `location` до `destination`, не заходящие в `blocked = visited − {location}`; **первый** хоп — из `permitted_neighbors − visited`; дальше хопы **не** ограничены `permitted` (занятость и буфер дальше первого хопа не учитываются); назначение терминально (путь заканчивается там, где впервые достиг его). Цель: наименьшее число рёбер, при равенстве — лексикографически наименьший путь как кортеж номеров. Решение: `Decision(path[1], context.tick)`; допустимого пути нет → `None`; `location == destination` → `None` (нулевой хоп, пакет не пересылается в текущий узел).

Алгоритм `TBR_enumeration._search` (итеративное углубление, явный стек, без рекурсии):

```
for limit in 1 .. N-1:
    stack = [(location,)]; best = None; frontier = 0
    while stack:
        if expansions == max_call_expansions: return INCOMPLETE      # путь не возвращается
        path = stack.pop(); expansions += 1                           # вход в префикс
        if path[-1] == destination: best = min(best, path по (len, path)); continue
        if len(path)-1 == limit:   frontier += 1; continue            # граничный префикс
        for nb in соседи path[-1] по ВОЗРАСТАНИЮ номеров (кладутся в обратном порядке):
            if nb in blocked or nb in path: continue
            if len(path) == 1 and nb not in first_hops: continue
            push(path + (nb,))
    if best: return ROUTE(best)
    if frontier == 0: return NO_ROUTE
return NO_ROUTE
```

Один «вход» = один префикс, снятый со стека; корень входит заново на каждом уровне. Нет BFS, нет расстояний, нет отсечения, нет возврата при первом найденном пути, нет кэша между вызовами (кэш строк смежности внутри вызова — только ускорение чтения).

**Ручные прогоны** (метка «ручной расчёт»; числа входов 12, 5, 10, 8 совпали с контрольными значениями в `probes/tbr_enum/check_tbr_enum.py`):
- *G5, пример 1 из части C* (`location 0`, `dest 4`, `visited {0}`, `permitted {1,2}`). Уровень 1: корень, `(0,1)`, `(0,2)` — три входа, оба граничные. Уровень 2: корень, `(0,1)` (тупик), `(0,2)`, `(0,2,3)` — четыре входа. Уровень 3: корень, `(0,1)`, `(0,2)`, `(0,2,3)`, `(0,2,3,4)` — пять входов; последний — назначение. Всего 12 входов, путь `(0,2,3,4)`, решение **2**.
- *Пример 2* (рёбра 0–2, 0–4, 2–3, 3–4; пакет в 2, `visited {0,2}`, `permitted {0,3}`): первые хопы `{3}`, `blocked = {0}`. Уровень 1: корень, `(2,3)` — граничный; уровень 2: корень, `(2,3)`, `(2,3,4)`. Всего 5 входов, решение **3**.
- *Пример 3* (G5, `permitted {1,2,4}`, `visited {0}`): уровень 1: корень, `(0,1)`, `(0,2)`, `(0,4)` — 4 входа; `(0,4)` — назначение; решение **4** (в скрипте этого случая нет).
- *Полный граф K4* (узлы 0–3, все пары; `location 0`, `dest 3`, `visited {0}`, `permitted {1,2}`): уровень 1 — корень, `(0,1)`, `(0,2)` (3 входа, узел 3 как первый хоп не допущен); уровень 2 — корень, `(0,1)`, `(0,1,2)`, `(0,1,3)`, `(0,2)`, `(0,2,1)`, `(0,2,3)` (7 входов); пути `(0,1,3)` и `(0,2,3)` равной длины, меньший — `(0,1,3)`. Всего 10 входов, решение **1**.
- *Нет пути* (рёбра 0–1, 1–2; `location 0`, `dest 3`, `permitted {1}`): уровень 1 — 2 входа; уровень 2 — 3; уровень 3 — 3 входа, граничных префиксов нет → `no_route`; 8 входов, ответ `None`.

**Трассировка стека на G5, пример 1** (ручной расчёт по тексту `_search`; смежность: 0: {1,2,4}, 1: {0}, 2: {0,3}, 3: {2,4}, 4: {0,3}; `blocked` пуст, `first_hops = {1,2}`). Термины: *префикс* — начало пути, лежащее на стеке; *вход* — одно снятие префикса со стека (счётчик `expansions`); *уровень* — один проход цикла `for limit`. Стек записан слева направо, верх справа; соседи кладутся в обратном порядке, поэтому первым снимается меньший номер.
- Уровень `limit = 1`. Стек `[(0)]`. Вход 1: снят `(0)`; узел 4 пропущен (не первый хоп из `permitted`); кладём `(0,2)`, затем `(0,1)`: стек `[(0,2),(0,1)]`. Вход 2: снят `(0,1)`, число рёбер 1 равно `limit` — граничный, `frontier = 1`. Вход 3: снят `(0,2)`, граничный, `frontier = 2`; стек пуст, пути нет, `frontier` не нуль — следующий уровень.
- Уровень `limit = 2`. Вход 1: снят `(0)`, стек `[(0,2),(0,1)]`. Вход 2: снят `(0,1)`; сосед 0 уже в пути, ничего не кладётся. Вход 3: снят `(0,2)`; сосед 0 в пути, сосед 3 свободен: стек `[(0,2,3)]`. Вход 4: снят `(0,2,3)`, число рёбер 2 равно `limit` — граничный, `frontier = 1`; стек пуст.
- Уровень `limit = 3`. Входы 1–3 те же, что на уровне 2; после входа 3 стек `[(0,2,3)]`. Вход 4: снят `(0,2,3)`, число рёбер 2 меньше `limit`; сосед 2 в пути, сосед 4 свободен: стек `[(0,2,3,4)]`. Вход 5: снят `(0,2,3,4)`, это назначение: `best = (0,2,3,4)`; стек пуст, уровень завершён с маршрутом.
- Итого входов 3 + 4 + 5 = 12; решение — второй узел пути `(0,2,3,4)`, то есть **2**.

## 4. Нативный эталон и его отличие

`exhaustive_simple_path_reference`: тот же допустимый класс путей, но один обход в глубину **всех** допустимых простых путей с последующим выбором по `(число рёбер, путь)`. Ручной расчёт на G5, пример 1: корень, `(0,1)`, `(0,2)`, `(0,2,3)`, `(0,2,3,4)` — 5 входов против 12 у итеративного углубления (то же решение 2). Границы эталона (в коде написано): `DEFAULT_MAX_NODES = 12`, `DEFAULT_MAX_EXPANSIONS = 100000`; при `N > max_nodes` — `TBRSearchIncomplete("max_nodes")` **до** поиска. Ручной расчёт: при `N = 132 > 12` эталон с умолчаниями отказывает, не начав поиск. Это исключение **не ловится** в `_schedule`: оно прерывает `Simulator.run` (часть A, раздел 5). Граница не даёт ни маршрута, ни «пропуска пакета».

## 5. Границы `TBR_enumeration` и что значит `None`

В коде написано: `DEFAULT_MAX_CALL_EXPANSIONS = 200000`, `DEFAULT_MAX_CELL_EXPANSIONS = 200000000` — «independent safety controls; NOT paper settings». Обоснования выбранных значений в коде нет (не установлено). Правило: вызов, исчерпавший `max_call_expansions` при ещё не пустом стеке, **неполон**: возвращает `None` (пакет ждёт), считается в `incomplete_call_budget`, **никогда** не даёт маршрут по частичной работе и не переходит на другой маршрутизатор. Когда сумма входов за ячейку превысила `max_cell_expansions`, политика исчерпана: каждый следующий вызов сразу возвращает `None` (`skipped_after_cell_budget`), то есть маршрутизация в этой ячейке фактически прекращена, пакеты ждут до TTL. `None` в этой политике означает одно из четырёх: нет пути; нулевой хоп; неполный поиск; пропуск после исчерпания ячейки. Различаются они только счётчиками `stats()`.

## 6. Отказы и крайние случаи

- **Назначение в `visited`** (и не текущий узел): путей нет, ответ `None` до конца жизни пакета. **Занятые узлы** дальше первого хопа не учитываются (маршрут может проходить через узел, который занят в этом тике).
- **Пакет «в ловушке»:** все допустимые первые хопы посещены или не допустимы → `None` (в отличие от BFS-TBR, который в такой ситуации шагнул бы в посещённый узел).
- **Проверка входов:** индексы вне `[0, N)` и «допустимые соседи не являются соседями» — `ValueError` (прерывает прогон); симметричность и бинарность матрицы здесь **не** проверяются (проверяет `validate_adjacency` в эталоне) — в прогоне матрицу уже проверил симулятор (вывод из чтения).
- **Повтор:** неполный вызов повторяется каждый тик и каждый раз тратит до `max_call_expansions` входов (вывод из чтения).
- **Топология меняется между вызовами:** каждый вызов считает заново, кэша между вызовами нет.

## 7. Стоимость (вывод из чтения; времена не приводятся)

Три факта. (1) Входы вызова — сумма по уровням `k = 1 … d*` числа допустимых префиксов длиной до `k` рёбер, где `d*` — кратчайшее ограниченное расстояние; число входов растёт примерно как степень ветвления в степени `d*`, то есть экспоненциально по `d*`. (2) Иллюстрация (ручной расчёт, условная, **не** гарантированная нижняя оценка для реальных вызовов): если бы у каждого узла было не менее `δ` соседей, а первый хоп и `visited` ничего не исключали, простых префиксов с `k` рёбрами было бы `δ(δ−1)…(δ−k+1)`; при `δ = 12`, `k = 4` это `12·11·10·9 = 11880` (префиксы, дошедшие до назначения, из счёта выбывают, поэтому в вызове их меньше). (3) Не установлено: значение `δ` на реальных графах и доля неполных вызовов. Средняя степень при равномерном распределении спутников по сфере (гипотеза): `N·(3500/(2·7421))² ≈ 0,0556·N`, то есть ≈ 7,3 при `N = 132` и ≈ 22 при `N = 396` (расчёт по радиусу орбиты 7421 км и дальности 3500 км); на больших плотных графах поиск, вероятно, не завершится в границах (гипотеза). Память: стек префиксов, каждый — кортеж длины до `d*+1`.

## 8. Отношение к статье (TBR)

Установлено чтением: в [11] TBR — «brute-force» на каждом промежуточном узле; что перебирается (все простые пути? пути во времени?), цель (хопы или задержка), данные на каждом хопе и **рост стоимости TBR с `N` — не сказаны**. Стоимость в [11] выражена в единицах элементарных операций, не в секундах. Отдельно от чтений текста (индекс, раздел 6, говорит именно о них): чтение рисунка стоимости статьи GLR (arXiv 2108.08523v1, рис. 5) на глаз, без единицы; см. `FIGURES_VS_OURS_RU.md` в материалах проекта; в чтениях текста статьи рост стоимости TBR не описан. По этому чтению на глаз рост TBR порядка 3,85 раза от `N = 132` до `N = 396`; полный перебор простых путей с таким ростом, возможно, несовместим (гипотеза, не вывод: единица неизвестна, а что именно перебирали авторы, не установлено). Поэтому: брутфорс статьи не установлен; `TBR_enumeration` — независимая реконструкция одного из возможных толкований, **не код статьи** и не доказательство того, что именно это перебирали авторы; BFS по умолчанию — допущение, помеченное в графиках как «TBR = BFS».
