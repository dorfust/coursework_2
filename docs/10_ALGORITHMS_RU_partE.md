## 1. Назначение

GLR — маршрутизатор «хоп за хопом» на выученных оценках. Для каждого назначения `d` и каждого кандидата `v` модель выдаёт число `S[d, v]`; маршрутизатор берёт допустимого, ещё не посещённого соседа с **наименьшей** оценкой. Смысл оценки в `policies.py` не указан; в `model.py` (докстринг `HopRegressor`) написано: `S[d,v]` оценивает оставшиеся хопы, а не стоимость пути с задержками. Модель не знает ни пакета, ни узла, где он лежит: на входе только граф тика (вывод из чтения, раздел 2). Название «GLR» принадлежит статье GLR (arXiv 2108.08523v1); наш класс — независимая реконструкция (докстринг `policies.py`: «Independently written reconstruction policies; no upstream source port»), модель — «not author architecture» (докстринг `model.py`).

## 2. Что читает на самом деле

- Из пакета: **только** `packet.destination` и `packet.visited` (в `choose` больше нет обращений к пакету).
- Из контекста: `adjacency` (каждый вызов), `permitted_neighbors`, `tick` (идёт в `Decision`); `ranges_km` — **только** в необязательном режиме задержки (`ModelConfig.uses_delay`).
- Не читает: `packet.location`, `source`, `hops`, `header`, `size_bytes`, `expiry_tick`, очереди и занятость (кроме того, что отражено в `permitted_neighbors`), `cfg` симуляции.
- Вывод из чтения: решение зависит от узла лишь через `permitted_neighbors` (его строит симулятор для узла головы очереди) и через `visited`; оценка `S[d, v]` от узла не зависит.

## 3. Контракт предиктора, сборка и алгоритм

**Контракт** (комментарий в `GLR.__init__`): `GLR(predictor, n, model_config=None)`; в режиме только топологии (по умолчанию, `features = "adjacency_spliced_two_hop"`, псевдоним `"topology_only_ablation"`) вызывается `predictor(A, None)`; в необязательном режиме задержки (`"adjacency_spliced_two_hop_propagation_delay"`, в статье такого входа нет — комментарии `config.py`, `features.py`) — `predictor(A, ranges_km)`. Результат после `np.asarray(..., dtype=float)` обязан иметь форму `(n, n)` и быть конечным; оси — `[destination, candidate]`. Предиктор и веса фиксированы на экземпляр: «Replacing weights/predictor requires a NEW GLR instance, never cache reuse». `model_config=None` заменяется на `ModelConfig()` и проверяется `validate()`.

**Как предиктор строится в одиночном прогоне** (`simulate.py`, `run_single`, ветка `GLR`): `torch.set_num_threads(cfg.torch_threads)`, `torch.use_deterministic_algorithms(True)`; `load_trained_model(checkpoint_run, "cpu")`; `require_supported_model`; при режиме задержки совпадение скорости света; `asdict(training_config.orbit) == asdict(cfg.orbit)`; `cfg.phase_seed` не входит в затравки обучения, проверки и теста (иначе `ValueError`); затем `GLR(lambda adjacency, ranges: predict_hops(model, adjacency, ranges), cfg.orbit.n, training_config.model)`. Как предиктор строит набор опытов (`experiments.py`), для этого описания **не установлено** (файл не читался).

**Что вычисляет `predict_hops`** (`model.py`, `graph.py`): проверка смежности и формы `(model.n, model.n)` (иначе `ValueError("checkpoint requires the trained N and node ID ordering")`); режим `eval`; входы `low = [A]` (ширина `N`) и `high = [A|Q]` (ширина `2N`); `Q` — матрица: 1,0 для соседей, 0,5 для пар «только через общего соседа», 0 иначе, диагональ 0 (`preprocessed_structure`); распространение по исходной бинарной `A` (обе стороны ребра); результат — `numpy [N, N]`; диагональ ровно `0.0`; **без** оракула достижимости, маски соседей и посещённых, симметризации и обрезки значений.

**Проза алгоритма `choose`.** (1) Проверить матрицу и размер. (2) Оставить кандидатов: допустимые соседи, которых нет в `visited`; если их нет — вернуть `None` до любых обращений к кэшу. (3) Собрать ключ кэша. (4) Если ключ изменился — один вызов предиктора на весь граф, иначе взять сохранённую матрицу. (5) Выбрать кандидата с наименьшим `(оценка, номер)`.

```
choose(packet, context):
  A = validate_adjacency(context.adjacency)          # bool, симметрична, диагональ 0
  if A.shape != (n, n): raise ValueError("GLR fixed-N adjacency mismatch")
  cand = [v for v in context.permitted_neighbors if v not in packet.visited]
  if not cand: return None                           # предиктор не вызывается, счётчики не меняются
  model_config.validate(); cfg_json = canonical_json(asdict(model_config))
  if uses_delay:
      ranges = validate_ranges(context.ranges_km, n); delay_features(A, ranges, cfg)   # только проверка
      key = (A.tobytes(), ranges.tobytes(), cfg_json)
  else:
      ranges = None;  key = (A.tobytes(), cfg_json)    # ranges не проверяются и в ключ не входят
  if key != _key:
      S = np.asarray(predictor(A.copy(), None | ranges.copy()), dtype=float)   # время -> inference_seconds
      if S.shape != (n, n) or not all finite: raise ValueError("GLR predictor must return finite [destination,candidate] scores")
      inference_count += 1;  _key, _scores = key, S.copy()
  else: cache_hits += 1
  best = min(cand, key = lambda v: (_scores[packet.destination, v], v))
  return Decision(best, context.tick)
```

**Правила ничьей и значений** (в коде написано): побеждает наименьшая оценка; при **точном** равенстве чисел `float64` — меньший номер узла (допуска нет). Конечные отрицательные оценки допустимы; «нулевого маркера недостижимости» нет. Назначения в ключе нет: одна матрица обслуживает все назначения и все узлы тика. Кэш — **одна запись**: любая смена ключа вытесняет её; возврат к прежней топологии — снова промах. Вторая часть ключа (`cfg_json`) у одного экземпляра постоянна, пока не подменён атрибут `model_config` (вывод из чтения: это защита от повторного использования кэша при смене конфигурации).

## 4. Что значит `None` и что делает симулятор

`None` возвращается ровно когда `cand` пуст: нет допустимых соседей (отсутствуют рёбра, соседи заняты, буфер полон) **или** все допустимые уже в `visited`. Симулятор (`Simulator._schedule`, описание в части A) записывает `last_wait = "no_route_or_no_permitted_candidate"`, увеличивает `route_wait_calls`; пакет остаётся головой очереди и опрашивается в следующий тик, когда узел свободен. **Запасного маршрута нет**: ни обхода посещённых, ни возврата назад, ни перехода к другой политике (`stats()["unreachable_behavior"]`: «no reachability oracle; no candidate waits, including all-neighbors-visited»). Пакет заканчивается по общим причинам (TTL, повторы, лимит хопов — часть A). Для недостижимого назначения GLR всё равно выдаёт решение, пока есть непосещённый допустимый сосед (вывод из чтения: оракула достижимости нет).

## 5. Пример «ручной расчёт»: четыре узла, ВЫДУМАННАЯ матрица оценок

Рёбра: 0–1, 0–2, 1–3, 2–3, `N = 4`. Матрица `S[d, v]` **выдумана** для примера, к обученной модели отношения не имеет (диагональ 0 — как после `predict_hops`):

| `d \ v` | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 0 | 0,0 | 1,1 | 0,9 | 2,0 |
| 1 | 0,9 | 0,0 | 2,1 | 1,2 |
| 2 | 1,1 | 2,2 | 0,0 | 0,9 |
| 3 | 2,1 | 1,0 | 1,0 | 0,0 |

Допущение примера: `visited` содержит узлы, где пакет уже побывал, включая текущий; как симулятор заполняет `visited` — **не установлено** (раздел E2.11).

1. Пакет в узле 0, `d = 3`, `visited = {0}`, `permitted = (1, 2)`. Кандидаты (1, 2). `S[3,1] = 1,0 = S[3,2]`: равны, ключи `(1,0; 1)` и `(1,0; 2)`, побеждает **1**: `Decision(1, tick)`.
2. То же, но узел 1 занят: `permitted = (2)` → побеждает **2** (лучший по оценке сосед отсутствует в `permitted`, берётся худший из оставшихся).
3. Пакет в узле 1, `d = 3`, `visited = {0, 1}`, `permitted = (0, 3)`: узел 0 посещён, кандидат один — **3**.
4. Отрицательная оценка. Пусть сырой выход дал `S[3,0] = −0,5` (допустимо: обрезки нет). Пакет в узле 1, `visited = {1}`, `permitted = (0, 3)`: `S[3,3] = 0,0` (диагональ), `−0,5 < 0,0` → выбирается **0**, хотя назначение — прямой сосед. Вывод из чтения: назначение в коде не выделено; встречается ли такое у обученной модели, **не установлено**.
5. Ожидание. Пакет в узле 3, `d = 2`, `visited = {0, 1, 3}`; узел 2 занят: `permitted = (1)`, кандидаты пусты → `None`, пакет ждёт. В следующем тике узел 2 свободен: `permitted = (1, 2)`, кандидат **2** → `Decision(2, tick)`.
6. Кэш. Вызовы с непустыми кандидатами: тик 10, граф `A1` (случай 1) — промах; тик 10, другой узел, `A1` — попадание; тик 11, `A1` — попадание; тик 12, граф `A2` (ребра 1–3 нет) — промах; тик 13, снова `A1` — промах (запись одна). Итог: `inference_count = 3`, `cache_hits = 2`. Вызов случая 5 с пустыми кандидатами в счётчики не входит.
