## 1. Что поставить
- VS Code и расширение Python; конфигурации запуска имеют тип `debugpy` [К], для него нужен Python Debugger (по документации VS Code, не проверялось) [В].
- Python 3.10–3.14 с python.org [К: `start.py` принимает версии от 3.10 до 3.14 включительно]. По успешному запуску известна только 3.14, остальные не проверены. В установщике отметьте «Add python.exe to PATH» и «py launcher», затем откройте НОВОЕ окно терминала. Python из Microsoft Store (путь с `WindowsApps`) `start.py` для перезапуска отвергает [К].
- Интернет при первом старте: качается CPU-сборка torch [К]. Размер загрузки и место на диске: [Н].
- Короткий путь проекта без OneDrive и Dropbox, например `C:\cw2`: при пути длиннее 100 знаков или при OneDrive/Dropbox `start.py` лишь предупреждает [К].

## 2. Открыть папку
File → Open Folder → корень проекта (там лежат `start.py`, `src`, `experiments`, `configs`). Из другой папки `start.py` останавливается с кодом 12 [К]. Файлы `.vscode` берутся из открытой папки. Файл `ssn-hops.code-workspace` необязателен (раздел 6).

## 3. Интерпретатор
- Первый старт: `.venv` ещё нет, его создаёт сам `start.py` [К]. Выберите любой установленный Python 3.10–3.14: Ctrl+Shift+P → Python: Select Interpreter. Если выбран Python вне диапазона, `start.py` ищет другой (`.venv`, затем `py -3.14` … `py -3.10`), печатает «Re-starting start.py with …» и передаёт код выхода дальше; голый `python` не пробуется [К].
- Не создавайте окружение средствами VS Code: `.venv` делает `start.py`. Если `.venv` с python, но без метки `.venv\ssn_ready.json` уже есть, `start.py` пропустит создание и повторит шаги pip [К].
- После первого старта можно выбрать `.venv\Scripts\python.exe` для подсказок редактора [В]; запуск от этого не зависит: дочерние процессы идут через python из `.venv` [К].
- Ни `settings.json`, ни workspace-файл не задают `python.defaultInterpreterPath`: выбор за вами [К].
- Терминал VS Code `.venv` сам не включает (`python.terminal.activateEnvironment` = false) [К]. Поэтому `python` в терминале — не интерпретатор `.venv`; ручную команду с пакетами проекта запускайте как `.venv\Scripts\python.exe …` [В].

## 4. Run Python File
Откройте файл и нажмите Run Python File. Каждый из четырёх вызывает `main()` из `start.py` [К, по docstring]:

| Файл | Что запускает | Эквивалент в терминале |
|---|---|---|
| `start.py` | полный прогон, объём статьи (220 ячеек, 5 обучений) [Р: счёт по наборам; в файлах наборов этих чисел нет, счёт — в `docs/06_CONFIGS_SUITES_RU.md` § 4] | `python start.py` |
| `start_quick.py` | быстрый сквозной прогон; **числа НЕ результаты**; длительность НЕ измерена | `python start.py --quick` |
| `start_tbr_enumeration.py` | только второй прогон `TBR_enumeration` | `python start.py --tbr-enumeration --skip-main` |
| `start_dry_run.py` | `run_all.py` только проверяет и печатает команды | `python start.py --dry-run` |

Запускатели `start_*.py` я как файлы не читал: связь с опциями взята из `start.py` и описания запуска [Н для их текста].
- Первый старт любого из четырёх начинается с установки (`.venv`, pip, CPU-torch, проба импорта); `--dry-run` её тоже делает [К]. **ОЦЕНКА** [О] полного прогона 4,6 / 5,0 / 5,9 ч — не измерение; CGR при N > 132 не измерялся. Прерванный прогон продолжить нельзя [К].
- Опции (`--output-root`, `--models`, `--setup-only`, `--stages` …) через Run Python File не передать: запускатели дописывают только аргументы из терминала. Для них используйте терминал: `python start.py …`; все опции — `docs/11_START_AND_PLOTS_RU_partB.md`.
- Стадии train и execute печатают мало (раз в минуту `[heartbeat]`) [К].

## 5. Четыре конфигурации `launch.json`
Ctrl+Shift+D (Run and Debug) → выбрать конфигурацию → F5 [В]. Вопросов и аргументов у них нет [К].

| Имя | `program` |
|---|---|
| Start: full run | `${workspaceFolder}/start.py` |
| Start: quick smoke test | `${workspaceFolder}/start_quick.py` |
| Start: TBR enumeration only | `${workspaceFolder}/start_tbr_enumeration.py` |
| Start: dry run | `${workspaceFolder}/start_dry_run.py` |

У всех четырёх одинаково [К]: `type` = `debugpy`, `request` = `launch`, `cwd` = `${workspaceFolder}`, `env` = `{"PYTHONUTF8": "1"}`, `console` = `integratedTerminal`, `justMyCode` = true, `subProcess` = false.
- Это те же файлы, что в Run Python File, но под отладчиком [В].
- По смыслу ключа `subProcess` = false отладчик не подключается к дочерним процессам, а `start.py` запускает `run_all.py` как дочерний [В]: точки останова внутри `experiments` и `src` не сработают. Как именно debugpy понимает этот ключ: [Н].
- Насколько отладчик замедляет многочасовой прогон: [Н]. Для полного прогона отладчик не нужен [В].
- Код выхода `start.py` VS Code может не показать (не проверено) [Н]. Чтобы его узнать, запустите команду в терминале и сразу введите: cmd — `echo %ERRORLEVEL%`; PowerShell — `$LASTEXITCODE`.

## 6. Что делают `settings.json` и workspace-файл
Настройки лежат в ДВУХ местах с почти одинаковым содержанием [К]. Ни `start.py`, ни `run_all.py` их не читают; они влияют на редактор и его терминал [В].

| Ключ | Смысл | settings.json | workspace |
|---|---|---|---|
| `python.analysis.extraPaths` = `src` | редактор находит пакет `ssn_hops` (подсказки) | да | да |
| `python.terminal.activateEnvironment` = false | терминал не включает `.venv` | да | да |
| `terminal.integrated.env.windows`: `PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8` | UTF-8 в терминале Windows | да | да |
| `terminal.integrated.defaultProfile.windows` = Command Prompt | терминал по умолчанию — cmd | да | да |
| `files.exclude`, `files.watcherExclude`, `search.exclude` | скрывают `__pycache__`, `*.egg-info`, `.venv`; наблюдатель и поиск пропускают ещё `outputs` | да | да |
| `PYTHONPATH` = `src` в терминале (Windows и Linux) | `src` в пути поиска терминала | да | нет |

- Папка `.venv` скрыта из проводника (`files.exclude`), но существует.
- Совпадающие ключи двух файлов VS Code сводит по своим правилам; как именно: [Н]. Простейший путь — открыть папку, как в разделе 2; workspace-файл можно не открывать.
- `.vscode/extensions.json` я не читал [Н].
