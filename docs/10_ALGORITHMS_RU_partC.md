## 1. Назначение

На каждом вызове выбрать среди допустимых соседей того, у кого наименьшее число хопов до назначения по текущему графу. Это «оракул числа хопов»: он видит весь текущий граф, но не знает ни истории пакета, ни расстояний, ни очередей. Роль в эксперименте — эталон сравнения (по замыслу проекта к нему привязаны парные разности; в коде этого не сказано).

## 2. Что читает на самом деле

`context.adjacency` (каждый вызов), `packet.destination`, `context.permitted_neighbors`, `context.tick` (в коде написано, docstring `HopOracle`: «reads only context.adjacency, packet.destination, context.permitted_neighbors and context.tick»). **Не читает** `packet.visited`, `packet.location`, `ranges_km`, `size_bytes`, TTL.

## 3. Алгоритм

```
choose(packet, context):
  dist = BFS-расстояния в хопах ОТ назначения по context.adjacency   # -1 если недостижим
  candidates = [v for v in permitted_neighbors if dist[v] >= 0]
  if not candidates: return None
  chosen = min(candidates, key = (dist[v], v))     # меньше хопов, при равенстве — меньший номер
  return Decision(chosen, context.tick)
```

BFS (`HopOracle._bfs`): очередь, старт — назначение с расстоянием 0, соседи через `np.flatnonzero(adjacency[node])`; граф неориентированный, поэтому расстояние от назначения равно расстоянию до него. **Правило ничьей:** `(расстояние, номер)` — минимальный номер среди равных.

Кэш (`_distance_list`, в коде написано): хранятся расстояния для **последней** топологии (приватная копия матрицы) по точному `int` назначения; при следующем вызове матрица сравнивается целиком (`np.array_equal`, форма и dtype тоже); при отличии кэш сбрасывается. Если тип не `np.ndarray` 2-D числового dtype или назначение не точный `int`, BFS считается заново без хранения. Решение всегда берётся из списка расстояний и **текущего** `permitted` — кэш хранит только расстояния, не решения.

## 4. Примеры «ручной расчёт»: где BFS и перебор расходятся

Определение перебора (подробно — часть C2): допустимы простые пути от `location` до `destination`, не заходящие в `visited` (кроме текущего узла); первый хоп — из `permitted` без `visited`; выбирается путь с наименьшим числом рёбер, при равенстве — лексикографически наименьший; решение — второй узел пути.

**Граф G5:** узлы 0…4, рёбра 0–1, 0–2, 0–4, 2–3, 3–4. Пакет в узле 0, назначение 4. BFS от узла 4: соседи 0 и 3 получают расстояние 1; из 0 — узлы 1, 2 получают 2 (узел 3 уже 1). Итог `dist = [1, 2, 2, 1, 0]` для узлов 0…4.

*Пример 1 (занят узел 4, `permitted = {1,2}`, `visited = {0}`).* BFS-TBR: `dist[1] = dist[2] = 2` → выбирает **1** (меньший номер). Узел 1 — тупик (его единственный сосед — 0). Перебор: через 1 простого пути к 4 нет; через 2 есть путь `0-2-3-4` → выбирает **2**. TSR на этом же графе (все дальности равны): заголовок `[0,4]`, узел 4 не допустим → `None`, ожидание. Три разных ответа: 1 / 2 / ожидание.

*Пример 2 (пакет вернулся: ping-pong).* Граф: рёбра 0–2, 0–4, 2–3, 3–4 (узел 1 изолирован). Пакет в узле 2, пришёл из 0 (`visited = {0,2}`), назначение 4, `permitted = {0,3}`. BFS от 4: `dist[0] = 1`, `dist[3] = 1`, `dist[2] = 2`. BFS-TBR: оба кандидата имеют 1 → **0**, то есть шаг назад (`visited` не читается). Перебор: узел 0 в `visited` блокирован → путь `2-3-4` → **3**.

*Пример 3 (совпадение).* G5, `permitted = {1,2,4}`, `visited = {0}`. BFS-TBR: `dist[4] = 0` → **4**. Перебор: путь `0-4` из одного ребра → **4**.

*Условие совпадения* (вывод из чтения; рассуждение по определению, не запускалось): пакет в первом вызове на источнике (`visited = {source}`) и среди допустимых соседей есть `v` с `dist[v] = dist[source] − 1`. Тогда кратчайший путь из `v` не проходит через источник, длина перебора равна `dist[source]`, а первые хопы всех кратчайших путей — ровно такие `v`; обе процедуры берут наименьший номер. Во всех остальных случаях (пакет ушёл с источника; лучший сосед занят или его буфер полон; допустимые соседи уже посещены) решения могут различаться, и **насколько часто** — не установлено.

## 5. Что значит `None`

`None` — нет допустимого соседа, из которого назначение достижимо (допустимых нет, или все недостижимы). Симулятор записывает ожидание, пакет остаётся головой очереди и опрашивается снова на следующем тике (часть A, раздел 6). Недостижимое назначение и пустой `permitted` для BFS-TBR неразличимы.

## 6. Отказы и крайние случаи

- **Возврат и колебания** (вывод из чтения): `visited` не учитывается, а кандидат не обязан быть ближе текущего узла. Поэтому пакет может уйти в тупик (пример 1) или вернуться (пример 2). Предел `hops >= 2·N` закрывает пакет как `failed` с причиной `hop_limit`; бесконечного блуждания симулятор не допускает. При TTL по умолчанию (3000 тиков) и 15 тиках на хоп пакет успевает сделать не более 200 хопов (ручной расчёт: 3000 / 15), а предел при `N = 132` равен 264, поэтому при умолчаниях блуждающий пакет заканчивает TTL, а не предел; предел действует лишь при длинном TTL.
- **Назначение — сосед:** его расстояние 0, поэтому если оно допустимо, оно выбирается всегда.
- **Занятые и переполненные соседи** исключены до вызова (`permitted`): лучший по числу хопов узел, занятый в этом тике, не выбирается, пакет идёт к следующему по `(расстояние, номер)` или ждёт.
- **Топология меняется между вызовами:** BFS пересчитывается при любом изменении матрицы (кэш сравнивает её содержимое); решение всегда по текущему снимку.
- **Ошибки:** индекс вне диапазона и подобное — обычные исключения Python (проверок аргументов нет, как сказано в docstring).

## 7. Стоимость (вывод из чтения; времена не приводятся)

Один BFS: `N` вершин, на каждую `np.flatnonzero` по строке длины `N` → `O(N²)`. BFS нужен один раз на пару (топология, назначение); при каждом вызове сравнение матриц `np.array_equal` — ещё `O(N²)`; затем отбор среди `permitted` — `O(степень)`. За тик вызовов не больше `N` (часть A). Память: копия последней матрицы (`N²` элементов; для `N = 396` — `156 816`, ручной расчёт) и по списку из `N` чисел на назначение. Рост с `N` — полиномиальный (степень два на вызов), в отличие от перебора.

## 8. Отношение к статье

Установлено чтением статей: TBR в [11] — «brute-force» на каждом промежуточном узле; что перебирается и что оптимизируется — **не сказано**; [11] называет TBR «всегда оптимальным» по задержке и доле потерь. Открытый код LSNS отдельного класса TBR не содержит (не доказано, что перебора нет); ближайший по духу — Дейкстра по текущим координатам при одинаковой скорости, что даёт минимум хопов (вывод чтения, не класс TBR). Поэтому: «на каждом хопе» наш `HopOracle` совпадает с описанием; «перебор» и «цель оптимизации» — **не решается**; BFS по умолчанию — **допущение**, а не алгоритм статьи. По математике (общее знание, не из статьи): BFS даёт те же расстояния, что Дейкстра с одинаковым весом рёбер.
