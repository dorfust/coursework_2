- start.py вызывает его после основного прогона (`run_poststep`, часть A, раздел 2, п. 9): `<python .venv> experiments/paper_style_plots.py --summary <папка>/summary.json --out <папка>/paper_style`. Условия (часть A): код run_all.py равен 0, нет `--dry-run`, нет `--quick`, среди стадий есть `aggregate`. После второго прогона (`--tbr-enumeration`) тот же вызов делает `run_second` (часть B). Сбой даёт код 13 start.py и не меняет `summary.json`.

Вывод из чтения: `python` в терминале VS Code не из `.venv` (часть A, раздел 1), поэтому лучше указать интерпретатор `.venv` явно.
- Нужно (docstring и `load_matplotlib`): Python 3.10+, стандартная библиотека, matplotlib с backend Agg; для `--summary` ещё пакет `ssn_hops` (`prepare_plot_data`). Какие пакеты тянет импорт `ssn_hops.experiment_plots`: не установлено.

Сокращения опций НЕ запрещены (в отличие от start.py): `allow_abbrev` не задан, действует умолчание argparse (вывод из чтения).
**Папки** (`check_target`): `--out` и `--style-demo` должны не существовать или быть пустыми; файл вместо папки, непросматриваемая папка, непустая папка, одна и та же папка для обеих опций дают строку `ERROR: ...` и код 2 до любой работы. ## 3. Откуда берутся числа
Скрипт читает ключи сводки: `complete` (частичная = `complete` не True), `policy_names`, `groups[]` с `grid`, `variant`, `axis`, `x`, `controls` (`n`, `failure_probability`), `policies[<политика>].equal_replicate[<метрика>]` (`mean`, `se_of_mean`, `n_nonnull`), `enumeration_completeness.completeness_share_pooled`; и ключи заданий `plots[]` из `prepare_plot_data`: `grid`, `variant`, `axis`, `metric`, `curves[]` (`policy`, `x`, `y`, `se`, `nonnull_repetitions`, `completeness_share`), `exclusion_reason`.
- **Какой бакет.** `choose_spec`: для оси `failure_probability` предпочитается сетка `interruption`, для оси `n` — `size`, вариант `reference`; нет такого — берётся первый с строкой `NOTICE: no ...; using ...`; если бакетов несколько, остальные перечисляются как «not drawn». Совпадение имён сеток набора с этими константами по файлам наборов не проверялось (часть C называет сетки `interruption` и `size`).
- **Что усредняется.** Значения — `equal_replicate`: среднее по повторениям (наборам seed) с равными весами, только по сопоставленным повторениям (`NOTE_DELAY`). Задержка — только ДОСТАВЛЕННЫХ пакетов. Потеря — `failure_fraction` (по подписи `experiment_plots.LABELS`: failed/generated, незавершённые пакеты — `pending_fraction`, здесь не рисуется; вывод из чтения).
- **Столбики ошибок** — только в файлах `<имя>_se.png`: одна стандартная ошибка среднего (`se_of_mean`; не доверительный интервал). Для сводки нативного формата `_stats` сверяет её с `sample_sd/√n_nonnull`; для обычной не читал. У точки с одним наблюдением SE нет, столбика нет (`SE_NOTE`). Под рисунком печатается диапазон `n_nonnull` по сериям (`se_note`).
- **Два файла на рисунок:** `<имя>.png` (без столбиков ошибок, «стиль статьи») и `<имя>_se.png` (с ними). Размер 8,0 × 6,6 дюйма, 150 dpi (`render`), то есть 1200 × 990 пикселей (ручной расчёт). Для сводки с шестью заданиями — до 12 файлов.
- **Серии:** `ORDER` = GLR, TBR_style_hop_oracle, CGR_contact_plan, TSR_source_dijkstra, TBR_enumeration; подписи (`NAMES`) GLR, TBR, CGR, TSR, TBR-enum. Остальные политики сводки (например, нативный эталон TBR) не рисуются и перечисляются в примечании «Policies of the summary not drawn in this figure».

- **fig3a, fig3b.** Подзаголовок «(N = …)» из `controls.n` групп бакета: одно значение — оно, несколько — «varies: …», нет — «unknown». Примечания: `NOTE_P` (x = 100·p; p — вероятность срыва за активный тик нашей реконструкции; смысл «interruption probability» статьи не проверен), `NOTE_DELAY` или `NOTE_LOSS` (потеря включает истечение TTL и исчерпание повторов; определение потери в статье неизвестно), `NOTE_STYLE`.
- **fig4_delay_vs_N.** Порядок столбиков в группе GLR, TBR, CGR, TSR (TBR-enum пятым, если есть); подзаголовок «p = …%» из `controls.failure_probability`·100. Примечания `NOTE_FIG4`, `NOTE_DELAY`. Подробности стиля — часть D2.
- **fig4_loss_vs_N.** `prepare_plots` не отдаёт потерю на оси `n` (`METRICS` там: задержка, секунды на вызов, секунды симулятора), поэтому `curves_from_groups` читает `groups[*].policies[*].equal_replicate.failure_fraction` сама. Заголовок: «EXTRA figure, not present in the paper (its Fig. 4 has no loss panel)». Если у какой-то политики нет записи в группе, `KeyError` даёт пропуск «malformed summary data» (вывод из чтения).
- **fig5.** Кривые затрат НЕ сопоставимы с рис. 5 статьи: единица статьи неизвестна, наш TBR — не перебор, порядок не сопоставим. `prepare_plots` для затрат на оси `n` оставляет GLR, TBR, CGR, нативный эталон и TBR_enumeration, а TSR исключает (`FIG5_POLICIES`); строку «paper Fig.5 legend: GLR, TBR, CGR only» печатает сам скрипт как `exclusion_reason` по умолчанию (`spec_c.get(...)`), а что отдаёт подготовка сводки, не установлено. Скрипт берёт `COST_KEYS` (GLR, TBR, CGR, TBR-enum), TBR подписан «TBR (BFS)», примечание «TSR is omitted as in revision 3b (rule: …)». `NOTE_COST`: секунды ЦП на вызов маршрутизатора ЭТОЙ реализации, включая вывод модели; единица статьи неизвестна. Линейная ось начинается с 0; в логарифмической нет `ylim`, и рисунок пропускается, если нет положительных значений.
- **Красные проценты** у точек TBR-enum — `completeness_share_pooled`·100: доля вызовов поиска, завершившихся полностью; `NOTE_ENUM` добавляет, что неполный поиск = пакет ждёт, и значения TBR-enum включают эти ожидания (часть C, раздел 2).
- **Метка TBR.** В каждом рисунке `NOTE_MAIN`: «Reconstruction, not the authors' results; TBR = BFS hop oracle, not the paper's brute force». Заголовок начинается с «Reconstruction, not the authors' results» (`TITLE_HEAD`), при PARTIAL добавляется «/ PARTIAL» и первое примечание `NOTE_PARTIAL`.
- **Примечания** печатаются серым мелким шрифтом внизу (по ширине 125 знаков, `render`); поле снизу = 0,12 + 0,021·(число строк) (`render`). Ручной расчёт: при 16 строках поле 0,456, высота области осей 0,424 высоты рисунка; как это ляжет на картинку, не установлено.

## 5. Пропуски и пустоты
Рисунок пропускается со строкой `SKIPPED figure <имя>: <причина>`; причины в коде: нет группы оси `failure_probability` (fig3a, fig3b); нет группы оси `n` (оба fig4); нет данных `route_seconds_per_call` (оба fig5); «no drawable policy in the summary for this figure»; «no policy has any value for this figure»; «no positive value for a logarithmic axis»; «malformed summary data: …» (при `KeyError`, `TypeError`, `ValueError`, `IndexError` в `attempt`). Серия без значений не рисуется (примечание «No data in this summary, series not drawn»); позиция x без значений убирается («position not drawn»); пропавшая точка — разрыв (у столбиков нет столбика, у линий `NaN`), нулём никогда (`prune`, `draw_bars`, `draw_lines`). Если рисунков не получилось, папка `--out` не создаётся (печатается сообщение), код 1.
Вывод из чтения: в сводке второго прогона (набор `suite_tbr_enumeration`: одна точка по каждой оси; политики TBR, TSR, TBR_enumeration) каждый рисунок получит одну точку или одну группу, а GLR и CGR будут отсутствовать; минимума числа x в `make_job` и `prune` нет.
