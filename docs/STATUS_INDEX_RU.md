# Статус файлов описания: что читать и что ещё верно (редакция 5)

## 1. Что это за файл

Это индекс, а не описание. Он не пересказывает содержимое ни одного файла: он говорит, где читать и что из уже написанного ещё верно, и держит состояние проекта один раз на весь набор описаний. Всё, что здесь сказано о содержимом файла, взято из чтения самого этого файла либо из файла, который на него ссылается; где источник — только перечень папки (имя и размер), это сказано словом «перечень». Метки: **[К]** так написано в коде, **[В]** вывод из чтения, **[Р]** ручной расчёт, **[Н]** не установлено. Ничего не исполнялось никем из авторов этого текста: ни программа, ни проверка, ни построение рисунка — это метка метода, а не состояние проекта; состояние проекта сказано один раз в разделе 2.

«По сообщению пользователя, режимы checks, smoke и full рабочего процесса GitHub Actions завершились успешно на раннере GitHub (Linux) на дереве до поздних правок; после правок кода и текстов снова успешно завершились режимы checks и smoke (режим full не повторялся); сообщённые длительности: checks 1 мин 53 с, smoke 17 мин 57 с (в первой серии: 2 мин 8 с, 17 мин 47 с и full 4 ч 55 мин 25 с); не уточнено, что измерено: весь запуск или одно задание; журналы, артефакты и результаты авторам этого текста недоступны. «Завершились успешно» значит лишь, что задания окончились без ошибки по правилу самого рабочего процесса; это не утверждение о научной верности, не запуск на Windows и не запуск на компьютере пользователя.»

Формулировка о запусках рабочего процесса GitHub Actions приведена здесь один раз; `docs/05_EXPERIMENTS_RU_partE.md` (раздел G) и `docs/06_CONFIGS_SUITES_RU.md` (раздел «Статус текста») повторяют её дословно [В]. Фраза «ничего не запускалось» внутри прежних файлов описания — метка метода (текст писан чтением), а не состояние проекта. Запись о запусках на компьютере пользователя — `README.md`, раздел 2; прогонов не добавляет ни один другой файл описания [В].
