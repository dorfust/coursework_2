## 1. `probes/tbr_enum/check_tbr_enum.py`: TBR_enumeration против нативного эталона

**Что сравнивает.** Решение политики `TBR_enumeration` (`src/ssn_hops/tbr_enum.py`, метод `choose`) с решением нативного эталона `exhaustive_simple_path_reference` (`tbr_reference.py`): эталон возвращает путь, решением считается его второй узел (`reference_decision`); нет пути или путь из одного узла — `None`. Скрипт проверяет, что при полном поиске обе стороны выбирают одного и того же соседа. Это проверка эквивалентности на малых графах, а не работы в симуляторе.

**Запуск.** Из корня проекта (docstring); вывод из чтения: корень скрипт вычисляет по расположению файла (`ROOT = parents[2]`, в `sys.path` добавляется `ROOT/src`), так что текущая папка на импорт не влияет, а файл должен лежать как есть, в `probes/tbr_enum/`.
```
.venv\Scripts\python.exe probes\tbr_enum\check_tbr_enum.py
.venv\Scripts\python.exe probes\tbr_enum\check_tbr_enum.py --cases 3000 --max-nodes 8 --seed 7
```
Какой Python: нужен тот, где есть numpy (импорт на верхнем уровне) и пакет `ssn_hops` из `src`; Python проекта 3.10–3.14 (часть A). Почему именно интерпретатор `.venv`, а не голый `python`: поставляемые настройки VS Code окружение не активируют (`python.terminal.activateEnvironment` = false, часть A), и голый `python` падает с `ModuleNotFoundError: No module named 'numpy'`; активация в текущем окне (`.venv\Scripts\activate.bat`) равносильна. Тянет ли `import ssn_hops` пакет torch, не установлено; импорты вне `try`, при неудаче — трассировка (вывод из чтения).
| Опция | По умолчанию | Отказ |
|---|---|---|
| `--cases` | 2000 | меньше 1 — `parser.error` |
| `--max-nodes` | 8 | меньше 2 — `parser.error` |
| `--seed` | 12345 | — |
Верхняя граница `--max-nodes` не проверяется; эталон вызывается с `max_nodes=64`, что будет при большем числе узлов, не установлено; docstring предупреждает, что стоимость растёт экспоненциально.

**Три блока проверки.**
1. **Случайное сравнение** (`random_comparison`). Для каждого случая: число узлов от 2 до `--max-nodes`; вероятность ребра из (0,2; 0,35; 0,5; 0,8); положение и адресат случайные (могут совпасть); посещённые = положение плюс каждый прочий узел, кроме адресата, с вероятностью 0,25 (адресат посещённым не бывает); разрешённые первые шаги = соседи положения, каждый с вероятностью 0,7. Эталон: `max_expansions` 10**7. Политика: `TBR_enumeration(max_call_expansions=10**7)`, вызывается через `choose` с тиком 5; если решение не `int` или `not_before_tick` не равен 5 — `AssertionError` (трассировка). Случай ПРОПУСКАЕТСЯ и СЧИТАЕТСЯ, если эталон поднял `TBRSearchIncomplete` или у политики `stats()["incomplete_call_budget"]` не нуль; пропуск не считается несовпадением.
2. **Четыре ручных образца** (`hand_fixtures`): «counterexample 1» (ожидаемое решение 2, расширений 12), «counterexample 2» (3; 5), «K4 with node 3 busy» (1; 10), «no route» (`None`; 8). Сравниваются решение и точное `total_expansions`. Числа выведены вручную; несовпадение может быть и ошибкой ручной трассы (docstring). Дополнительно для каждого образца проверяется арифметика счётчиков (`algebra_problems`): число вызовов = завершённые (маршрут, нет маршрута, нулевой путь) + неполные по бюджету вызова + пропущенные после бюджета ячейки; `total_expansions` = сумма завершённых и неполных; неполные = их число × `max_call_expansions`; `stats` сериализуется без `NaN`.
3. **Правила бюджета** (`budget_checks`): бюджет вызова 1 на цепочке 0–1–2–3 даёт `None`, один неполный вызов, `completeness_share` 0,0; бюджет ячейки 1: первый вызов возвращает 1, второй `None`, `cell_budget_exhausted` истинно, `skipped_after_cell_budget` равно 1; значения бюджета 0, −1, `True`, 1,5 должны вызывать `ValueError`.

**Что печатается.** Строки: «random comparison: N cases, K compared, S skipped (a side was incomplete), M mismatches» (K = N − S; до пяти строк `MISMATCH case=… reference=… enum=…`), «hand fixtures: P problems», «budget rules: P problems» (строки `PROBLEM …`), затем итог. **PASS** — единственная строка `PASS`, код 0. **FAIL** — строка «FAIL: <блоки через запятую>», код 1; FAIL дают: несовпадения, случай «пропущены ВСЕ случаи» (`skipped == cases`), проблемы любого из двух других блоков. Код 2 — ошибка аргументов (argparse). Формат, не результат: `random comparison: <N> cases, <K> compared, <S> skipped ..., <M> mismatches`, где K = N − S. По сообщению пользователя, запуск 2026-11-14 напечатал `2000 compared, 0 skipped`: пропущенных случаев нет, все 2000 сравнены действительно; число случаев равно умолчанию (`--cases` 2000), а значение `--seed` в сообщении не указано — какая выборка была, не установлено. Полного прогона у него нет; журнала у авторов нет.

**Что PASS НЕ доказывает** (docstring и чтение): согласия на графах больше `--max-nodes`; равенства чисел расширений на случайных графах (счётчики сверяются только на четырёх образцах); работы политики в симуляторе, плана, агрегации, рисунков, обмена JSON; скорости. Кроме того (вывод из чтения): при фиксированном `--seed` выборка каждый раз одна и та же; пропущенные случаи не проверялись, их доля видна только в строке итога; эталон сам не проверяется, он мерка, и сам написан в том же проекте; что `TBR_enumeration` — код статьи, не доказывается и не утверждается.

**Что прислать.** Команду, весь stdout и stderr, код выхода (`echo %ERRORLEVEL%` в cmd), `python --version`.

## 2. `probes/check_comment_only/check_comment_only.py`: «та же программа, другие комментарии»

**Зачем.** В семи файлах (`policies.py`, `simulator.py`, `sim_config.py`, `contacts.py`, `tbr_policy.py`, `tbr_reference.py`, `tbr_enum.py`) должны были измениться только комментарии и тексты docstring. Файлы записаны целиком, и случайная правка буквы в строке кода изменила бы поведение; исполнять код авторы не могли. Скрипт сравнивает на вашем компьютере исходный (эталонный) файл и новый файл. Python 3.10+, только стандартная библиотека. Рядом лежит `README_RU.md` с теми же командами и конкретными путями репозитория; здесь шаблоны.

**Команды** (порядок аргументов всегда: СНАЧАЛА эталон, потом новый; прямые и обратные косые черты допустимы, `_path`):
1. Режим папок, шесть пар: `python check_comment_only.py --pairs-from-folders <ЭТАЛОН>\src\ssn_hops <НОВАЯ>\src\ssn_hops`. Сравниваются только `*.py` с именами в обеих папках: `contacts.py`, `policies.py`, `sim_config.py`, `simulator.py`, `tbr_policy.py`, `tbr_reference.py`. Файлы только в одной папке печатаются строкой `INFO: ... exists in only one of the two folders and is not compared`; для `tbr_enum.py` это ожидаемо (в эталонной выгрузке его нет): он НЕ проверен этой командой.
2. Явная пара для `tbr_enum.py`: `python check_comment_only.py <ЭТАЛОН tbr_enum.py> <НОВЫЙ tbr_enum.py>`. Эталон этого файла лежит в более ранней подготовленной ревизии, не в закреплённой выгрузке (README).
Режим пар принимает и любое чётное число аргументов. Код 2: нет аргументов, нечётное число, неверное число аргументов или не папки в режиме папок, нет общих `*.py`; `-h`/`--help` печатает справку, код 0. После двух команд должно быть видно семь строк `RESULT:` (шесть + одна).

**Три слоя** (`check_pair`):
1. **AST.** Оба файла читаются как UTF-8 и разбираются `ast.parse` (ошибка чтения, не UTF-8, синтаксиса — FAIL с сообщением); из деревьев удаляются docstring модуля, классов и функций (пустое тело получает `Pass`, одинаково с обеих сторон); `ast.dump` без атрибутов (номера строк не учитываются) должен совпасть: «AST: AST-EQUAL». Иначе «AST: FAIL» с первым отличающимся оператором верхнего уровня и, внутри `def`/`class`, первым отличающимся внутренним.
2. **Токены.** Потоки `tokenize` обоих файлов без `COMMENT`, `NL` и без токенов `STRING` и `NEWLINE` операторов-docstring (диапазоны строк записаны до удаления) должны совпасть: «TOKENS: EQUAL (N tokens compared)»; иначе «TOKENS: FAIL» с первым отличием (вид, текст, строка). Вывод из чтения, зачем два слоя: токены видят различия записи, которые AST скрывает (лишние скобки, `1.0` против `1.00`).
3. **Построчный отчёт** (`line_report`, только информация, вердикт не меняет): `difflib` по строкам; добавленные и удалённые строки делятся на COMMENT, BLANK, DOCSTRING, OTHER-TRAILING-COMMENT (комментарий в конце строки кода) и OTHER; печатаются `LINES: added … (…)`, `LINES: removed … (…)` и до 20 строк OTHER с номерами.
Сверх слоёв (информация): размер, sha256, финальный перевод строки, стиль окончаний (LF, CRLF, смешанный) обоих файлов; строки `NOTE:` при отличии финального перевода строки или стиля окончаний.

**Вердикт и вывод.** Для пары `RESULT: PASS` только если AST равны И токены равны; иначе `RESULT: FAIL`. Итог «SUMMARY: N pair(s), K PASS, M FAIL». Код 0 — все пары PASS, 1 — есть FAIL, 2 — ошибка команды. Ожидаемо для набора (по README): все `RESULT: PASS`, в `LINES:` OTHER равно 0, а число `removed` для шага, который только добавлял комментарии, равно 0 (ненулевое — повод посмотреть: `difflib` может при выравнивании выдать лишние пустые строки или строки docstring). Образец формата дан в README (по тексту скрипта, не результат запуска).

**Что PASS НЕ доказывает.**
- Что тексты комментариев ВЕРНЫ (читаются глазами отдельно).
- Что программа правильна или запускается.
- Что «только добавления»: удалённые или изменённые комментарии и docstring тоже дают PASS; смотрите `LINES: removed`.
- Отсутствия прочих повреждений: потерянный финальный перевод строки, смена окончаний строк, пробелы в конце строки, замена пробела внутри комментария — только показываются или не видны.
- Известные пределы (README): токены docstring отбрасываются по номерам строк, поэтому замена строки в операторе после `;` на строке docstring в слое токенов не видна (слой AST её увидит: вывод из чтения); текст docstring безопасен, лишь если никакой код не читает `__doc__` (в пакете не проверялось); BOM и очень глубокая вложенность не разбираются отдельно, возможна трассировка (что делает `ast.parse` с символом BOM после `decode("utf-8")`, не установлено).
- Пара сравнивается только как заданная: эталон считается верным по определению; в режиме папок файлы без пары не проверяются.

**Что прислать.** Весь вывод обеих команд (stdout и stderr), включая FAIL и строки `INFO:`; код возврата каждой (`$LASTEXITCODE` в PowerShell, `echo %ERRORLEVEL%` в cmd); `python --version`. Ничего не вырезать и не править самому; личные части пути заменить на `...` можно только в строках `PAIR:`.
