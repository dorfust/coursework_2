## 1. Способы запуска (все ведут в main() файла start.py)

| Способ | Что написано в коде |
|---|---|
| `run.cmd [опции]` | Файл ревизии 4, переводы строк только LF, ни разу не запускался. Делает `cd /d "%~dp0"`, затем по очереди пробует `py -3.14`, `-3.13`, `-3.12`, `-3.11`, `-3.10` (проба `-c "import sys"`), в конце просто `python`; первый ответивший запускает `start.py %*`. Если никто не ответил: сообщение и `exit /b 11`. В заголовке файла: код выхода start.py становится кодом run.cmd. Как cmd обработает `exit /b` без числа и файл с LF: не установлено. |
| `python start.py [опции]` | Из папки проекта. Первая строка main(): проверка версии Python (см. раздел 4). |
| VS Code | Открыть папку проекта, открыть start.py, нажать Run Python File. Выбранный интерпретатор вне 3.10–3.14 приводит к перезапуску (раздел 4). |
| три запускателя | `start_quick.py` = `start.py --quick`; `start_tbr_enumeration.py` = `start.py --tbr-enumeration --skip-main`; `start_dry_run.py` = `start.py --dry-run`. В каждом: `sys.dont_write_bytecode = True`, своя папка добавляется в `sys.path`, `import start`, `start.main(ARGS + sys.argv[1:])`; дополнительные аргументы командной строки дописываются в конец. Запускателя полного прогона нет: это сам start.py. |
| `.vscode/launch.json` | Четыре конфигурации без вопросов: «Start: full run» (start.py), «Start: quick smoke test», «Start: TBR enumeration only», «Start: dry run». У всех: type debugpy, request launch, cwd `${workspaceFolder}`, env `PYTHONUTF8=1`, console integratedTerminal, justMyCode true, `"subProcess": false`. Аргументов нет. Принимает ли debugpy ключ subProcess именно так и что он делает: не установлено. |
| `ssn-hops.code-workspace` | Необязателен. Одна папка `.`; настройки: `python.analysis.extraPaths` = `src`, `python.terminal.activateEnvironment` = false, в терминале Windows `PYTHONUTF8=1` и `PYTHONIOENCODING=utf-8`, профиль терминала Command Prompt, исключения files.exclude / files.watcherExclude / search.exclude для `__pycache__`, `*.egg-info`, `.venv`, `outputs`. Переменных PYTHONPATH в нём нет. |
| `.vscode/settings.json` | То же, что в workspace, плюс `PYTHONPATH` = `${workspaceFolder}/src` (Linux) и `${workspaceFolder}\src` (Windows) для встроенного терминала. Как VS Code склеивает совпадающие ключи двух файлов: не установлено. |

Вывод из чтения: файлы `.vscode` и workspace влияют только на редактор и его терминал; start.py их не читает, а run_all.py сам задаёт PYTHONPATH дочерним процессам (функция env_overrides). Так как `activateEnvironment` = false, `python` в терминале VS Code — не интерпретатор `.venv`; ручные команды вида `python -m ssn_hops...` пакеты `.venv` не увидят (не проверено).

## 2. Что делает первый запуск, по порядку (run_start)

0. `configure_streams()`: вывод терпим к любой кодовой странице (непечатаемое заменяется на `?`).
1. Разбор команды: `build_parser()` (argparse, `allow_abbrev=False`, неизвестная опция — ошибка), `parse_stages`, `check_combinations` (запреты — в части B). Всё это завершается кодом 2.
2. **Строка ревизии.** Без `--revision`: `content_revision()` берёт файлы по четырём шаблонам MANIFEST_PATTERNS (`src/ssn_hops/*.py`, `configs/*.json`, `experiments/run_all.py`, `experiments/paper_style_plots.py`), сортирует по относительному пути (с `/`) и считает SHA-1 от строк `<путь>\0<sha256 байтов файла>\n`. Результат — 40 шестнадцатеричных знаков, это НЕ коммит git; печатается «revision manifest: N files». Если нет `experiments/run_all.py` или `src/ssn_hops/__init__.py` — код 12. Вывод из чтения: изменение любого файла из списка меняет строку; start.py, config.example.json и запускатели в неё не входят.
3. `read_base_config()`: читает `config.example.json` (UTF-8, BOM допускается), нужен JSON-объект, иначе код 12. Сам файл не меняется. В закреплённой выгрузке он называет старый набор и содержит «заглушку» ревизии; start.py в копии подменяет revision, output_root и suite (и stages, если задан `--stages`). Ключ `stages` без `--stages` берётся из этого файла (в закреплённой копии — все пять стадий).
4. Папка результатов: по умолчанию `outputs/run_<ГГГГММДД_ЧЧММСС>` в папке проекта (`quick_`, `tbr_enum_` — см. раздел 6).
5. Проверки до установки: разбор `--models` (часть B) и, при `--tbr-enumeration` без `--skip-main`, проверка длины пути второй папки (раздел 6).
6. **Установка** (`ensure_setup`; пропускается при `--no-setup`). Только если нет `.venv\Scripts\python.exe` (в POSIX `.venv/bin/python`, не проверено) или файла-метки `.venv/ssn_ready.json`, сначала печатается предупреждение `warn_if_risky_path` (путь проекта длиннее 100 знаков или в нём OneDrive/Dropbox; это только предупреждение). Затем:
   - если папка `.venv` есть, а python в ней нет: код 10, «удалите папку сами» (start.py ничего не удаляет);
   - `[1/4]` `<python> -m venv .venv`;
   - если метка уже есть: та же проба импорта (`import_probe`), успех — установка пропускается, неуспех — код 10;
   - иначе `[2/4]` `pip install --upgrade pip`; `[3/4]` `pip install torch --index-url https://download.pytorch.org/whl/cpu` (CPU-сборка, большая загрузка, нужен интернет); `[4/4]` `pip install -e ".[plot]"` (в тексте шага: подтягивает numpy и torch-geometric; состав extras в pyproject.toml я не читал — не установлено). Ко всем шагам добавлено `--disable-pip-version-check --retries 10 --timeout 60`. Любой ненулевой код шага — код выхода 10; в тексте: после сбоя pip — запустить ту же команду ещё раз (pip, как ожидается, повторно использует скачанное), после сбоя создания окружения — проверить, есть ли python в `.venv`, и если нет, удалить папку самим (ничего не удалено; это текст кода, не проверено).
   - проба импорта (до 900 с; одна и та же в обоих случаях, переключатель — файл-метка): в `.venv` импортируются numpy, torch, torch_geometric, matplotlib и печатаются версии пяти пакетов; при успехе `write_marker` создаёт `.venv/ssn_ready.json` (режим «x»: существующий не перезаписывается), при неуспехе метка не пишется, код 10.
   - при `--setup-only` на этом месте выход с кодом 0.
7. **Файл конфигурации.** `write_config` создаёт НОВЫЙ `outputs/_start/config_<метка>.json` (режим «x»; при занятом имени `_2`…`_99`, иначе код 10). Содержимое: копия базового конфига с revision, output_root, suite = `configs/suite_paper_scope.json` (с `--quick` — `configs/suite_quick.json`), при `--models` — путь к файлу `outputs/_start/models_<метка>.json` в `plan.models`.
8. **Вызов run_all.py** (`launch_run_all`): `<python .venv> experiments/run_all.py --config <файл> [--debug] [--dry-run]`, `--debug` добавляется, если нет `--quiet`. Рабочая папка — папка проекта. Печатается строка «run_all.py exit code: N». Docstring start.py больше не называет run_all.py «неизменённым»: шаг 6 перечисляет переданное (`--config`, `--debug`, `--dry-run`); по описанию состава ревизии run_all.py ИЗМЕНЁН (три новых ключа плана, часть C), решает код. run_all.py сам запускает стадии plan, train, execute, aggregate, plot отдельными процессами `python -m ssn_hops.experiments <стадия>`; обновление состояния печатается строкой `[heartbeat]` примерно раз в минуту на стадиях train и execute (run.progress_interval_s, по умолчанию 60).
9. **Послешаг** (`run_poststep`): только если код run_all.py равен 0, нет `--dry-run`, нет `--quick` и среди выбранных стадий есть `aggregate`. Если `experiments/paper_style_plots.py` или `<папка>/summary.json` не найден — послешаг пропускается без ошибки. Иначе: `<python> experiments/paper_style_plots.py --summary <папка>/summary.json --out <папка>/paper_style`. Сбой даёт код 13 и не меняет результат run_all.py; Ctrl+C — 130. Что строит этот скрипт — в следующей части.
10. С `--tbr-enumeration`: второй вызов run_all.py (часть B).

Ctrl+C: start.py сам сигнал не пересылает, консоль доставляет его и дочернему процессу; после трёх нажатий дочерний процесс убивается (`run_child`).

## 3. Что в первом запуске молчит
Стадии train и execute печатают мало (в баннере так и сказано). Прерванный прогон продолжить нельзя: надо начинать заново в новой папке (текст баннера и сообщение run_all.py).

## 4. Перезапуск в подходящем Python (restart_with_other_python)
`python_ok()`: версия не ниже 3.10 и ниже 3.15. Иначе:
- если задана переменная окружения `SSN_START_REEXEC`, перезапуск уже был: код 11 с подсказкой;
- `find_python()` перебирает кандидатов: python из `.venv` (только если есть метка); в Windows `py -3.14` … `py -3.10`; в POSIX `python3.14` … `python3.10` из PATH. Голый `python` НЕ пробуется. Каждый кандидат опрашивается командой `-c` (тайм-аут 30 с);
- `usable_python` отвергает версию вне диапазона, путь со словом `WindowsApps` (заглушка Microsoft Store), несуществующий файл и сам текущий интерпретатор;
- найден: печатается «Re-starting start.py with …», запускается `<найденный python> start.py <те же аргументы>` с `SSN_START_REEXEC=1` в текущей папке, код дочернего процесса передаётся без изменений (Ctrl+C при коде 0 даёт 130);
- не найден: код 11 и подсказка (ссылается на python.org, «Select Interpreter» и run.cmd).
Ctrl+C во время опроса интерпретаторов (прочитано в main()): вызов обёрнут в try, поэтому вместо трассировки печатается сообщение «Interrupted by Ctrl+C while looking for another Python. Nothing was deleted.» и возвращается код 130, как при любом прерывании.

## 5. Коды выхода start.py
Коды run_all.py передаются без изменений: **0** успех (о научной верности не говорит), **2** ошибка команды или конфигурации, **3** предполётная проверка (ничего не запущено), **4** стадия упала, **130** Ctrl+C. Собственные коды start.py: **2** (ошибка командной строки, запрещённая комбинация, `--output-root ""`, отказ `--models`, слишком длинный путь второй папки), **10** сбой установки (venv, pip, проба, нельзя записать файл или запустить процесс), **11** нет подходящего Python или сработал защитный флаг, **12** проблема config.example.json или состава проекта, **13** сбой послешага при успешном run_all.py, **14** сбой второго прогона после успешного основного (кроме 130: прерванный второй прогон возвращает 130). Если применимо несколько: 14 важнее 13, 13 важнее 0 (return в run_start). Если основной прогон закончился не нулём, второй не запускается, код основного возвращается как есть. Коды необработанных исключений Python в start.py не описаны.

## 6. Длина пути и имена папок
- **Имена.** Основная папка `outputs/run_<метка>`, при `--quick` `outputs/quick_<метка>`, при `--skip-main` `outputs/tbr_enum_<метка>`; вторая папка = основная + `_enum` (константа ENUM_SUFFIX), при `--skip-main` вторая папка совпадает с основной. Конфиги — `outputs/_start/`, окружение — `.venv`, график послешага — `<папка>/paper_style`. Раньше суффикс назывался `_tbr_enumeration`, в текущем коде `_enum`, решает код.
- **Проверка run_all.py** (`preflight_output`, только Windows): `len(str(<папка>\plan)) + 85 > 259` и длинные пути не подтверждены (реестр HKLM `…\Control\FileSystem`, `LongPathsEnabled`; нет значения — False; нет доступа — неизвестно) — код 3 «ничего не запущено»; больше 200 — только предупреждение. Константа 85 («самый длинный путь внутри плана») задана в коде, её происхождение не установлено.
- **Та же проверка в start.py** (`check_second_root_length`) применяется к ВТОРОЙ папке до начала основного прогона (код 2): если основная папка уже слишком длинна, run_all.py откажет основному прогону на своей предполётной проверке (код 3), иначе основной прогон прошёл бы, а отвергнут был бы только второй — через часы.
- Ручной расчёт: порог для папки: длина > 169 знаков (170 и больше) для второй, то есть основная от 165. Для основной папки по умолчанию `<корень>\outputs\run_<15 знаков метки>` (28 знаков после корня) второй путь отказывает при длине корня проекта от 137, сама основная — от 142; при корне 137–141 основной прогон пройдёт, а вторая папка будет отвергнута до старта. Короткий путь (в тексте кода пример `C:\cw2`) безопаснее.
- Предупреждение `warn_if_risky_path` (более 100 знаков или OneDrive/Dropbox) только печатается; run_all.py также предупреждает о синхронизируемой папке, пробелах и не-ASCII, Python из WindowsApps и о запуске вне venv. Эффекты антивируса, OneDrive и длинных путей «по документации», не проверено.
