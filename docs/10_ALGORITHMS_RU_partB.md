# 10. Алгоритмы. Часть B: TSR = `SourceDijkstra`

Файл `policies.py`: функция `source_dijkstra` и класс `SourceDijkstra` (`name = "TSR_source_dijkstra"`). Метки и общая механика — индекс и часть A. **Ничего не запускалось автором описания** — метка метода, не состояние проекта. О состоянии проекта: ревизия 5 на компьютере не запускалась; по сообщению пользователя режимы checks, smoke и full закончились без ошибок на дереве до поздних правок, а после правок повторены checks и smoke; журналы и артефакты авторам текста недоступны; «без ошибок» — только то, что задания закончились по собственному правилу рабочего процесса.

## 1. Назначение

TSR — маршрутизация от источника: путь целиком считается **один раз**, когда пакет впервые становится головой очереди на источнике, записывается в `packet.header` и дальше исполняется. Путь не пересматривается и не чинится (в коде написано: `stats()["repair"] = "none"`).

## 2. Что читает на самом деле

- При первом вызове: `packet.source`, `packet.destination`, `packet.size_bytes`, `packet.location`; `context.adjacency`, `context.ranges_km`, `context.cfg.rate_bytes_s`, `context.cfg.light_speed_km_s` (снимок **этого** тика).
- При каждом вызове: `packet.header`, `packet.hops`, `packet.location`, `context.permitted_neighbors`, `context.tick`.
- Не читает: `packet.visited`, `packet.expiry_tick`, очереди и занятость (кроме проверки следующего хопа в `permitted`).

## 3. Алгоритм

Проза. (1) Если заголовка нет — найти кратчайший по стоимости путь от источника к назначению; на других узлах пустой заголовок — ошибка. (2) Пустой список `[]` (назначение недостижимо) остаётся навсегда. (3) Следующий узел — `header[hops + 1]`; если он среди допустимых соседей — отправить в этом тике; если нет — ждать.

```
choose(packet, context):
  if packet.header is None:
      if packet.location != packet.source: raise ValueError
      packet.header = source_dijkstra(source, destination, size, context)
      source_searches += 1
  if packet.header == []:                       return None
  if hops >= len(header) or header[hops] != location: raise ValueError
  if hops + 1 >= len(header):                   return None   # защитная ветка
  nxt = header[hops + 1]
  if nxt not in context.permitted_neighbors:    return None
  return Decision(nxt, context.tick)

source_dijkstra(source, destination, size, context):
  labels = [inf]*N; labels[source] = 0.0; heap = [(0.0, source)]
  while heap:
      cost, node = pop(heap)
      if cost != labels[node]: continue                 # устаревшая запись
      if node == destination: return путь по predecessor
      for nb in узлы по возрастанию номера, где adjacency[node, nb]:
          w = size/rate_bytes_s + ranges_km[node, nb]/light_speed_km_s   # секунды
          if cost + w < labels[nb]:                     # строго меньше
              labels[nb] = cost + w; predecessor[nb] = node; push
  return []
```

**Правила ничьей** (вывод из чтения): из кучи сначала выходит запись с меньшим `(стоимость, номер узла)`; предшественник заменяется только при **строгом** улучшении; поэтому предшественником узла остаётся тот, кто вышел из кучи первым: меньшая собственная метка, при равных метках — меньший номер; более поздний кандидат равной стоимости его не заменяет. Ручной расчёт на абстрактных весах: метка узла `a` равна 5, метка узла `b` равна 3, ребро `a–d` стоит 3, ребро `b–d` стоит 5, номер `a` меньше номера `b`. Узел `b` выходит из кучи раньше (3 < 5) и даёт узлу `d` кандидата 8; позже узел `a` даёт тоже 8, это не строго меньше, и предшественник `d` остаётся `b`, хотя номер `a` меньше. Стоимость считается в секундах с плавающей точкой, в тиках не округляется.

**Вес ребра.** Сериализация одинакова для всех рёбер, различается лишь распространение. Ручной расчёт при умолчаниях: `18000 / 12500 = 1,44 с`; распространение `<= 3500 / 299792,458 ≈ 0,011675 с`. Путь из `k` хопов стоит не больше `1,44·k + 0,011675·k` и не меньше `1,44·k`, значит он дешевле любого пути из `k+1` хопов при `k <= 123` (`0,011675·123 ≈ 1,436 < 1,44`). Вывод из чтения: при умолчаниях TSR выбирает путь с **наименьшим числом хопов**, а среди путей с равным числом хопов — с меньшей суммой дальностей. Очереди, занятость и будущие контакты в стоимость не входят.

## 4. Что значит `None` и что делает симулятор

`None` возвращается в трёх случаях: пустой заголовок (источник был недостижим при единственном поиске); следующего хопа нет (защитная ветка); следующий узел **не** в `permitted` — ребра сейчас нет, или узел занят, или у него полный буфер (комментарий кода: «absent, busy or buffer-blocked edge waits until TTL»). Симулятор записывает ожидание, пакет остаётся головой очереди и опрашивается в следующем тике. Из-за этого короткая занятость соседа превращается в ожидание на тики, а исчезнувшее ребро — в ожидание до TTL.

## 5. Пример «ручной расчёт»: шесть узлов

Рёбра: 0–1, 1–2, 2–5, 0–3, 3–4, 4–5; источник 0, назначение 5; размер 18000 байт.

*Вариант 1: все дальности 1000 км.* Вес ребра `w = 1,44 + 1000/299792,458 ≈ 1,443336 с`. Куча: `(0;0)` → метки узлов 1 и 3 равны `w`. Выходит `(w;1)` (меньший номер): метка узла 2 = `2w`, предшественник 1. Выходит `(w;3)`: метка узла 4 = `2w`, предшественник 3. Выходит `(2w;2)`: метка узла 5 = `3w` ≈ 4,330007 (при `w` = 1,443335641), предшественник 2. Выходит `(2w;4)`: кандидат для узла 5 равен `3w` и не строго меньше метки — предшественник остаётся 2 (обе суммы вычисляются одинаково). Выходит `(3w;5)`: путь `[0,1,2,5]`.

*Вариант 2: ребро 0–1 длиной 3400 км, остальные 1000 км.* Вес ребра 0–1: `1,44 + 0,011341 = 1,451341`. Путь через 1 и 2: `1,451341179 + 2·1,443335641 ≈ 4,338012`; путь через 3 и 4: `3·1,443335641 ≈ 4,330007`. Заголовок `[0,3,4,5]`.

*Исполнение варианта 1.* Тик 20, пакет первым в очереди узла 0, `permitted = (1,3)`: заголовок строится, `header[1] = 1` допустим → `Decision(1, 20)`. После хопа пакет в узле 1, `hops = 1`, `header[1] == 1` верно, следующий — 2. Если в этом тике узел 2 занят, `2 ∉ permitted`, ответ `None`; на следующем тике снова. Если ребро 1–2 исчезло, ответ `None` повторяется каждый тик до TTL.

Для сравнения (граф и ручной разбор — часть C, раздел 4): на графе из 5 узлов с рёбрами 0–1, 0–2, 0–4, 2–3, 3–4 при занятом узле 4 TSR строит `[0,4]` и ждёт, BFS-TBR идёт в узел 1, перебор — в узел 2.

## 6. Отказы и крайние случаи

- **Назначение недостижимо при первом поиске:** заголовок `[]`, пакет ждёт до TTL.
- **Путь сломался позже:** маршрут не пересчитывается; пакет ждёт, пока ребро вернётся или истечёт TTL (гипотеза о причине многих отказов — ниже).
- **Голова очереди заблокирована:** поскольку FIFO строгий (часть A, раздел 6), остальные пакеты узла стоят за ней. Гипотеза «застрявшей головы» (не проверена): фиксированный путь плюс строгий FIFO дают долгую блокировку узла, пока TTL не спишет голову. Измерено пользователем один раз (проба с TTL, который не успевает истечь за окно наблюдения, N = 132, один компьютер, пять сценариев): отказов TSR при p = 0 не было, но около 28 % пакетов (0,28167, расчёт по записи пробы) к концу окна оставались недоставленными. Эти данные **не отделяют** механизм застрявшей головы от альтернатив (занятость, буфер, структура графа); причины завершения по пакетам не получены.
- **Пакет уже в назначении:** маршрутизатор не вызывается (после хопа симулятор закрывает пакет как доставленный).
- **Топология между вызовами:** путь строится по снимку первого вызова; изменения учитываются лишь через текущий `permitted`.
- **Ошибки:** `ValueError("source header missing after forwarding")`, `ValueError("source header/location mismatch")` — нарушение внутренней согласованности (прерывает прогон).

## 7. Стоимость (вывод из чтения; времена не приводятся)

Первый вызов: для каждого вышедшего из кучи узла `np.flatnonzero(adjacency[node])` стоит `O(N)`, итого `O(N²)` плюс `O(E log N)` на кучу, где `E` — число рёбер текущего графа. Каждый пакет ищет путь **не более одного раза** (`source_searches`). Остальные вызовы — проверка членства в кортеже `permitted` (`O(степень)`). Память: заголовок до `N` целых на пакет; метки и куча — `O(N)` временно.

## 8. Отношение к статье

Установлено чтением статей: TSR в [11] — один расчёт на источнике, путь в заголовке; при обрыве звена ждёт его восстановления или TTL; в GLR (arXiv 2108.08523v1) — Dijkstra один раз на источнике, путь в заголовке (пересказ чтения, не цитата). Наш TSR совпадает с этим описанием. **Не установлено:** по какому графу считает TSR статьи (один снимок или последовательность); цель оптимизации (у нас — секунды по формуле выше, на практике хопы); что значит «reconnects». Открытый код LSNS 2019–2022 при `msgPathLabel` и отсутствии следующего звена **пересчитывает** путь — это расходится и с текстом [11], и с нашим TSR; причина расхождения неизвестна. Механизм застрявшей головы — гипотеза, не утверждение статьи.
